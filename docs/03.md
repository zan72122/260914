## 1. 見た目の設計(本家の構図を踏襲)

- **一色の背景**(ピンク / 水色 / 紫 / 山吹など、レベルごとに変わる)の上に、**木の台**に乗った玩具が 1 つ置かれている構図。
- カメラは右上前方から約 35° 見下ろし、方位約 40°。**視野は狭め**(FOV 28°)で等角投影に近い見え方にする。呼吸のようにゆっくり(周期 9 秒、振幅 1.5°)揺れる。汽車がトンネルに入るときと駅到着時だけ、わずかに寄る。
- **光**: 太陽 1 灯(DirectionalLight、影は 1024px のシャドウマップ)+ 半球光。マテリアルはフラットな Lambert/Standard(roughness 高め)で、本家のようなマットな樹脂・木の質感。
- **色**: 各パーツはベタ塗り。楽器の色は v1 と同じ(たいこ赤、鈴金、鳥青…)。
- **汽車と貨車は全レベルの手前左に必ずいる**(本家と同じ)。汽車ループのレベルでは線路を走り、それ以外のレベルでは台の手前の短い側線に停まって貨車の楽器が拍に合わせて跳ねる。側線の右端にトンネル(次のレベルへの扉)がある。
- **おもちゃ箱**は、カメラに固定した手前下の木のトレイ(画面下端)。縦画面でも横画面でも同じ位置に見える。楽器は 3D の小さな玩具として並び、時々跳ねる。
- 画面の縦横比に応じて、台全体とトレイが必ず入るようカメラの距離を自動調整する。

## 2. レベル形式(3 種)

すべての形式で「8 列 = 8 ステップ」「高さ・行 = 5 音」という共通の決まりを守り、**拍が左から右へ進む**ことが見えるようにする。

### 2.1 汽車ループ(v1 の形式を 3D 化。1 層目は必ずこれ)
- 木の台の上に角丸ループの線路。8 本の太い枕木の外側に**差し込み口(ソケット)**が 8 つ。
- 楽器は箱から引き出してソケットに差す。メロディ楽器はソケットから伸びる**棒の上**に乗り、上下ドラッグで棒が伸び縮み(高いほど高い音)。
- 汽車が通ると楽器が揺れ、紙吹雪(小さな板)が舞う。
- 山のトンネルと扉、貨車への飛び乗りは v1 のとおり。

### 2.2 格子の島(新規)
- 木の台の上に **8 列 × 5 行のタイル**。行はカメラから見て奥ほど高く段になっている(奥 = 高い音、という**高さの自然な対応**)。
- 楽器は「塔」として任意のタイルに置ける。**1 列に複数**置ける(和音)。同じ列・同じ行には 1 つだけ。上限は 1 レベル 12 個。
- 拍は**光の棒**(半透明の板)が左端から右端へ 8 列を順に進むことで見える。棒が塔を通ると、タイルが光り、塔が跳ね、音が鳴る。
- 打楽器の塔は行にかかわらず同じ音(行は無視)。
- 取り消しは塔を持ち上げてタイル外で離す(トレイへ跳ねて戻る)。

### 2.3 オルゴール台(新規)
- 木の台の上に、軸を左右に向けた**大きな円筒**。1 周 = 1 ループ。手前から上へ回転する。
- 円筒の表面に **8 列 × 5 行の穴**。楽器は「ピン」として、**見えている穴**(手前〜上の約 3/8 周)に差し込む。1 列に複数可、同じ穴に 1 つ。
- 円筒の上端に**櫛(くし)と鍵盤**がある。ピンが上端に来ると櫛を弾き、その行の鍵盤が沈み、後ろに並ぶ**パイプ**が光って音が鳴る。パイプは右ほど短い(右 = 高い音)。
- ピンは回転して後ろに隠れ、また手前から現れる。差したピンが「回って戻ってくる」こと自体が、ループの見える化になる。
- 取り消しはピンが見えているときに持ち上げて円筒外で離す。

### 2.4 レベルの生成
- 1 層目: 汽車ループ。2〜4 層目: `train | grid | musicbox` からシード乱数で選ぶ(同じ形式が 3 回続くことは避ける)。
- 色テーマ(背景色 + 台の色)と楽器セットは v1 と同じ規則(1 層目に打楽器 2 種以上、4 層目にかえる)。

### 2.5 遷移・駅
- 扉を叩き、汽車がトンネルに入ると、その層の楽器が**貨車に飛び乗る**。カメラが横へパンし、新しい台が滑り込んでくる。汽車は貨車を連ねて新しい台の側線(または線路)に現れる。
- 4 層目の後は**駅**。汽車が停まり、貨車を叩くとふたが閉まる(ミュート)。隣の側線に青い空の汽車が待っていて、叩くと新曲(v1 と同じ)。

## 3. 触り方(3D での入力)

- Pointer Events → Raycaster。最初の指だけ有効。
- **持ち上げ**: 楽器(トレイ内・設置済み)にレイが当たったら持ち上げ、試し鳴らし。
- **運ぶ**: 指の位置から地面と平行な平面(高さ = 台の上 + 少し)へレイを飛ばした点に楽器を浮かべる。指の少し上に見えるよう、平面をやや奥に置く。
- **置き先の脈打ち**: 形式ごとの「空いている置き先」(ソケット / タイル / 見えている穴)が淡く光り、最も近いものは強く光る。
- **落とす**: 最も近い空き置き先(距離しきい値内)に吸い付き、弾んで鳴る。外なら弧を描いてトレイへ戻る。
- **音程**: 汽車ループでは棒の上下ドラッグ(v1 と同じ)。格子・オルゴールでは**置く場所そのもの**が音程なので、棒はない。
- **扉 / 汽車 / 貨車 / 新しい汽車のタップ**: v1 と同じ役割。汽車タップ = テンポ。
- 当たり判定はレイが当たる不可視の大きめの球(最小で画面上 64px 相当)にする。

## 4. 状態モデルの変更(保存形式 v2)

```ts
type LevelKind = 'train' | 'grid' | 'musicbox';
interface Placement { slot: number; pitch: number; inst: InstrumentId }  // slot = 列(0..7), pitch = 行(0..4)
interface Layer { kind: LevelKind; theme: ThemeId; instruments: InstrumentId[]; baseMidi: number; placements: Placement[]; muted: boolean }
```
- `train` は 1 列 1 つ、`grid` / `musicbox` は 1 列に複数(列 × 行で一意)。
- localStorage は `tune-train/song/v2`。v1 の保存データは読み込んで `kind: 'train'` を補って移行する。
- 音の仕組み(`Clock` / `Scheduler` / 楽器)は無変更。スケジューラの onStep は「その列の配置をすべて鳴らす」に変わるだけ。

## 5. アーキテクチャ

```
src/
  main.ts                 起動(WebGL 非対応時は静かに何も描かず、背景色のみ)
  app/
    game.ts               状態機械(waiting → level ⇄ transition → arriving → finale → depart)。3D 化に合わせて書き直し
    state.ts / levels.ts / storage.ts   モデル・生成・保存(v2 へ拡張)
  audio/                  無変更
  three/
    renderer.ts           WebGLRenderer、DPR 上限 2、影の設定、リサイズ
    camera.ts             カメラリグ(固定角 + 揺れ + 台全体が入る距離の自動計算 + 演出用の寄り)
    lights.ts             太陽光 + 半球光
    materials.ts          色パレットとマテリアルの共有(同色は 1 マテリアル)
    builders/
      instruments.ts      8 楽器の 3D 玩具(プリミティブ組み立て)
      train.ts            機関車・貨車・ふた・蒸気
      tray.ts             カメラ固定のおもちゃ箱トレイ
      tunnel.ts           トンネルと扉
      station.ts          駅
    levels/
      LevelView.ts        形式共通の interface(下記)
      TrainLevel.ts       汽車ループ
      GridLevel.ts        格子の島
      MusicBoxLevel.ts    オルゴール台
    effects.ts            紙吹雪・蒸気・光の棒などの一時オブジェクト
    picker.ts             Raycaster と当たり判定用の不可視ヒット球
  input/pointer.ts        無変更
```

`LevelView` interface(形式ごとの差はここに閉じ込める):
```ts
interface LevelView {
  root: Object3D;                       // 台ごと丸ごとパンできる
  build(layer: Layer): void;
  update(phase: number, hit: (slot, pitch) => number): void;   // 拍の見える化・跳ね
  dropTargets(): DropTarget[];          // 空いている置き先(位置・slot・pitch)
  placementWorldPos(p: Placement): Vector3;   // 飛び乗り演出の出発点・試し鳴らしの位置
  pickPlacement(ray): Placement | null; // 設置済み楽器の持ち上げ
  allowsPitchDrag: boolean;             // train のみ true
}
```

## 6. 実装ステップ(承認後)

1. **足場**: three を追加、レンダラ・カメラリグ・光・背景色・リサイズ・カメラ固定トレイ。Canvas 2D 描画コード(`src/render/*`)を削除。
2. **汽車ループの 3D 化**: 台・線路・ソケット・棒・楽器 3D 玩具・機関車・貨車・トンネル・蒸気・紙吹雪。v1 の遊びが 3D で全部できる状態にする。
3. **遷移と駅**: 貨車への飛び乗り、台の横パン、駅、ミュートのふた、新しい汽車。
4. **格子の島**: タイル段・塔・光の棒・置き先の脈打ち。
5. **オルゴール台**: 円筒・穴・ピン・櫛と鍵盤・パイプ・回転同期。
6. **レベル生成と保存 v2**: 形式のランダム化、v1 データの移行。
7. **仕上げ**: iPad で 60fps を狙う(タイルは InstancedMesh、同色マテリアル共有、影の範囲を台に限定)。当たり判定の大きさ、音量バランス。
8. **検証と記録**: 単体テスト更新、Playwright スモーク(WebGL、3 形式それぞれで置く→扉→駅→新曲)、`docs/04.md` に実装記録。

各ステップ完了ごとにコミットし、ブランチへプッシュする。

## 7. 検証方法

- **自動**: Vitest(状態 v2・移行・レベル生成の形式ルール)。Playwright は Chromium(SwiftShader)で WebGL を動かし、`?test` クエリのときだけ有効になるテスト用フック(3D オブジェクトの画面座標を返す)を使って、3 形式それぞれで「置く→鳴る→扉→次へ」を通す。コンソールエラーなし、各形式のスクリーンショット。
- **手動(利用者)**: `npm run build` → `dist/` を静的サーバへ → iPhone / iPad Safari。チェックリストは `docs/04.md` に書く。特に **発熱・フレームレート・タッチの吸い付き** を実機で確認したい。

## 8. リスクと対策

| リスク | 対策 |
|---|---|
| iPhone で影が重い | シャドウマップ 1024、影を落とすのは台の上の物だけ。重ければ設定を 512 に落とすフラグを用意 |
| 回転する円筒への置き先が掴みにくい | 穴を大きめに、吸い付き距離を広めに。見えている穴だけ光らせる |
| 縦画面で台が小さくなる | 台の縦横比を画面に合わせて 2 種類(縦用は奥行きを縮める) |
| 3D で「どこに置けるか」が分かりにくい | 空き置き先を常に薄くへこませ、持ち上げ中は脈打たせる(v1 と同じ原則) |
| WebGL が使えない端末 | 対象外(iOS Safari は全て対応)。失敗時は背景色だけ表示し例外を投げない |
| バンドル増加 | three は tree-shaking で約 150KB gzip 見込み。画像・モデル素材はなし |
