## 2. 各シーンの状態機械

数値は全て世界単位(セーフゾーンは 1000 角)。「ヒント」は無操作 8〜12 秒、「自動」は無操作 30 秒。

### 1 あつまれ(`01_gather.ts`)
```
scatter ──(全員が waver から CLUSTER_RADIUS=400 以内)──> clapping ──(1.5s)──> running ──(全員 exitX 越え / 4s)──> done
```
中央の一人だけが手を振る。タップ/ドラッグで近くの子が指について歩き、waver の近くまで来ると黄金角スロットに落ち着く。
ヒント=3人が自分から歩き出し waver が大きく振る。自動=全員がスロットへ。
**Phase 2 での変更**: 完了半径を 330 → 400。44人が落ち着く輪の外周が約 280 あり、分離力の揺さぶりで最後の数人が 330 の線上を漂って iPad で詰まっていました。

### 2 ぞろぞろ(`02_march.ts`)
```
line ──(全員の道上距離が exitX 越え)──> running ──(全員 exitX 越え / 4s)──> done
```
子は「道に沿った距離」1個で表現。指のドラッグの **道方向成分** が flow になり(`mergeFlow`、上限 300/s、`FLOW_DECAY=1.5`)、
列全体が流れる。逆向きのドラッグは既に出ている速い流れを打ち消さない(2本指が競合しない)。タップは跳ねる + 少しだけ流れる。
ヒント=先頭2人が自分から歩き出す。自動=一定の流れで押し出す。

### 3 くすぐり(`03_tickle.ts`)
```
crowd ──(全員が笑う)──> tumbling ──(全員 exitX 越え / 4s)──> done
```
1人だけ既に笑っている。タップ/なぞりで笑い開始、`SPREAD_INTERVAL=0.42s` ごとに半径 150 の隣へ確率 0.55 で伝染(輪が1つずつ広がる)。
終わると全員が転がって(`roll`)画面外へ。ヒント=最初の1人が大きく笑って隣を1人巻き込む。自動=伝染確率を上げる。

### 4 ボールプール(`04_ballpit.ts`)
```
rim ──(全員プールの中)──> overflow ──(1.6s)──> running ──(全員 exitX 越え / 4s)──> done
```
Phase 1 のまま。紙色だけ `SCENE_TINTS[3]` に付け替え。

### 5 ちょうちょ(`05_butterfly.ts`)
```
chase ──(ちょうが edgeX を越える)──> running ──(全員 exitX 越え / 4s)──> done
```
ちょうは押されている指の **平均位置** に指数で近づく(`approach`、`FOLLOW_RATE=3.4`)ので、2本指でも取り合いにならず、
どんなに速く指を振ってもオーバーシュートしない。指がないときは図形8の漂い。群衆はちょうを見上げて追う。
ヒント=ちょうが出口側へ小さく往復する(プレイヤーがすべき動作そのもの)。自動=そのまま飛び出す。
**Phase 2 での変更**: `edgeX` を `halfW-40` → `halfW-170`。指はガラスの端に届かず、ちょうは指に遅れて付いてくるため、
iPhone では **手では絶対に終われない** シーンになっていました(30秒の自動進行でしか終わらない)。

### 6 すべり台(`06_slide.ts`)
```
play ──(全員が滑り終える)──> running ──(全員 exitX 越え / 4s)──> done
```
役割は queue → climb(1.15s)→ top → slide(0.95s, `slideEase` で最初はそろそろ・途中から加速)→ landed の5つ。はしごは同時3人まで。
上をタップ=座っている子が滑る。それ以外のタップ/はしご方向へのドラッグ=最寄りの子がはしごへ。
ヒント=上の子が前ににじり、1人がはしごへ歩き出す。自動=1人ずつ自分で登る。
**Phase 2 での変更**: 送り出す子がもういない(またははしごが満員の)ときのタップは、上に座っている子を滑らせるようにしました。
これがないと、開始時から上に座っている1人は「その子に当たるタップ」でしか降ろせず、他をいくらタップしても何も起きない瞬間が生まれます。

### 7 かくれんぼ(`07_hide.ts`)
```
seek ──(全員 FOUND)──> running ──(全員 exitX 越え / 4s)──> done
```
7つの茂みの後ろに4人ずつ。茂みは子より **手前** に描くので隠れ場所になり、足が下からはみ出し、1人だけ頭が出ている。
茂みタップ/なぞり(`insideBush`、楕円 + タップは 30 の余裕)→ 中の全員が 0.5 秒の放物線で飛び出して(`ba!` + 笑い声 + 紙吹雪)笑う。
外したタップも「一番近い、まだ人が入っている茂み」を揺らすのでヒントになる。空になった茂みは alpha 0.82 に落ち着き、見つけ済みが一目で分かる。
ヒント=人の入っている茂みが 2.2 秒ゆれる。自動=0.8 秒ごとに1つずつ明け渡す。
**Phase 2 での変更**: 茂みの配置を全て 1000 角のセーフゾーン内へ(iPhone 縦では可視範囲がちょうどこの正方形で、はみ出した茂みは探せない)。

### 8 ふうせん(`08_balloon.ts`)
```
grass ──(全員が画面上端より上)──> away ──(1s)──> done
```
全員が風船を持ち(`hold` ポーズ、手は必ず頭より上に出る)、1人だけ既に浮いている。
タップ=その子(最大2人)が浮く。**上向き** のドラッグ(vy < -70)=通った子が最大3人浮く(§2.4)。
上昇は `riseSpeed`(指数立ち上がり、上限 240/s)+ 左右のゆれ(±26)+ 右への漂い(80/s)で、打ち上げではなく浮上。
ヒント=もう1人が自分から浮く。自動=0.5 秒ごとに1人ずつ。

### 9 ぐらぐらタワー(`09_tower.ts`)
```
build ──(6段)──> topple ──(1.6s)──> running ──(全員 exitX 越え / 4s)──> done
```
1人が土台、もう1人が登りかけの状態で始まる。タップ/上向きドラッグで最寄りの子が 0.75 秒かけて登る(同時に登るのは常に1人)。
**揺れは高さとともに増える**: `wobbleAmp(h) = 7 * (h-1)^1.7`(2段=7、6段=約 84)で、各段の揺れはその段の高さに比例。
6段で必ず崩れ、全員が同じ向きに `roll` で転がって笑いの山になり(`poro` + `laugh` + 紙吹雪)、起き上がって走る。怖い落下は存在しません。
ヒント=揺れが 1.2 倍になり、もう1人が登る。自動=0.7 秒ごとに1人ずつ。

### 10 おやすみ(`10_sleep.ts`)
```
night ──(全員 ASLEEP)──> morning ──(DAWN 2.6s + 1.6s)──> done ──> Director がシーン1を新規に作り直す
```
紙は `NIGHT = #6F68A8`(深いラベンダー・インディゴ)。**黒ではありません**(§9-3 の「怖さ要素なし」)。子は乗算色 `#C8C3E8` で夜に沈む。
星が1つだけ出ていて、2人だけ先に寝ている。**押した場所に星が生まれて瞬き**(`twinkle`、最大 30・古いものから再利用、なぞると星の軌跡)、
タップした付近の3人が **あくび(両手を伸ばす `climb` ポーズ、0.55 秒)→ 寝る**。寝息は 2.6 秒ごとに小さく。
全員寝ると空が朝へ、星が消え、子の色が白に戻り、Director が **シーン1を新しく作って** 始めから(§10-3 のリセット)。
ヒント=星が1つ灯って1人が寝る。自動=0.55 秒ごとに1人ずつ。

## 3. 遷移・無操作ヒント・自動進行

- 進行順は `src/scenes/order.ts`。`main.ts` はこの配列を引いて factory を並べます。
- 遷移は Phase 1 のまま **カメラのパンだけ**(暗転ゼロ、`PAN_STEP=1350` / `PAN_SEC=1.15`)。パン中は新旧どちらのシーンも生きていて、
  どちらに指を置いても反応します。
- 無操作ヒントは 8〜12 秒(毎回ランダム)、自動進行は 30 秒。どちらも `Director` が数え、シーン側の `onIdleHint` / `onAutoAdvance` を呼びます。
  **どちらも世界の中の出来事だけ**で表現しています(文字・矢印・UI はゼロ)。
- 10 の次は 1 で、シーン1は毎回 **新しく作り直される**(完全リセット)。

## 5. ドラッグの強さ(150 単位の子に合わせた再調整)

`src/crowd/behaviors.ts`:

- 遅いドラッグ(240 単位/秒 未満)= 指へ引き寄せ(`DRAG_PULL_FORCE=320`)。
- 速いドラッグ = 指の進行方向へ押す。力は `DRAG_PUSH_FORCE=1500`、ただし **900 単位/秒 で飽和**するので、
  必死に振っても穏やかに振ってもだいたい同じ手応えになります。
- 押された子の速度は `DRAG_MAX_SPEED=650` で頭打ち。群衆の減衰 2.4/s と合わせると惰行距離は約 270 単位
  = 身長 2 個未満・セーフゾーンの 1/5。**はっきり押せるのに、絶対に画面外へ吹き飛ばない**という条件を両方満たす値です。

## 6. デバッグフック(`window.__kids`)

画面には何も出ません。E2E とデバッグ専用です。Phase 1 からの追加を **太字**にしています。

| フック | 返すもの |
|---|---|
| `ready` | 起動完了 |
| `textCount()` | ステージ上の Pixi テキスト数(常に 0) |
| `kidCount()` | 現在のシーンの子の数 |
| `sceneName()` | `'gather'` … `'sleep'` |
| `sceneIndex()` | 進行順の番号(0〜9) |
| **`sceneCount()`** | シーン数(10) |
| `scenePhase()` | 上記の状態機械の状態名 |
| `sceneProgress()` | 0..1 |
| `panning()` | カメラがパン中か |
| `autoFired()` | 30秒の自動進行が発動済みか(E2E が「本当に指で進めた」ことを証明するのに使う) |
| `advanceScene()` | 次のシーンへ |
| **`gotoScene(i)`** | パンなしで i 番のシーンへ直接(スクショ用。ゲーム自身は絶対に使わない) |
| `finishScene()` | 現在のシーンを終わりまで進める |
| `idleHint()` / `autoAdvance()` | 無操作ヒント / 自動進行を手動で発火 |
| `fps()` | 実測 FPS |
| **`atlas()`** | 手続き生成したスプライトシートを data URL で(新ポーズの目視確認用) |

シーン側にも E2E 専用の読み取りフックがあります(`debugPhase()` は全シーン、ほかに
`debugFound()` / `debugFloated()` / `debugHeight()` / `debugWobble()` / `debugStars()` / `debugAsleep()` / `debugNight()`)。

## 7. テスト

```
npm run lint      # tsc + 文字ゼロ検査(42ファイル)
npm test          # vitest 129 件 / 16 ファイル
npm run build
npm run test:e2e  # Playwright 30 件(build してから preview に対して実行)
```

### 単体(vitest)
Phase 1 の 65 件に、Phase 2 の 8 シーン分 + 通しの Director テストを加えて **129 件**。
各シーンのファイルは「完了条件」と「ヒント/自動進行が掴むもの」を必ず検査します。
例: `tower.test.ts` は揺れが高さとともに **単調かつ非線形に** 増えること・6段で必ず崩れること・
どの段でも画面外へ振れないことを、`sleep.test.ts` は夜が黒くないこと(輝度・色相)・
夜明けの補間が一度も暗くならないこと・あくび中の子を寝たと数えないことを検査します。

### E2E(Playwright)
- `scenes.spec.ts`: 10 シーン × iPhone 390x844 縦 / iPad 1366x1024 横、さらに iPad 1024x1366 縦で 3 シーン(あつまれ・かくれんぼ・おやすみ)。
  各シーンで **idle / 指で遊んだ直後 / 終わり** の3枚を撮り、その3か所すべてで文字ゼロ検査をし、無操作ヒントも1回発火させて無害であることを見ます。
- `wordless.spec.ts`: 3端末で **10シーン全部を訪れて触って** 文字・ボタン・Pixi テキストがゼロであること、
  マルチタッチ、回転、そして 1→10→1 の遷移に暗転がないこと。
- `loop.spec.ts`: **デバッグフックを一切使わず**(読み取り専用の `sceneName` / `autoFired` のみ)、
  合成のタップとドラッグだけで 10 シーンを通し、シーン1に戻るまでを再生します。
  ポーリングのたびに `autoFired() === false` を検査するので、「30秒の救済で進んだ」ことは起こり得ません。

## 8. 仕様との差分(Phase 2)

1. **シーン1の完了半径 330 → 400**(上記 §2)。見た目は変わりません(群衆は自分で 220 程度にまとまる)。
2. **シーン5の出口 `halfW-40` → `halfW-170`**(上記 §2)。指が届かない = 手で終われない、を直すため。
3. **シーン6の「余ったタップ」**(上記 §2)。「間違った操作が存在しない」(§2 補助ルール)を守るため。
4. **シーン10のあくび**: 01.md の表は「子が寝息」とだけ書いていますが、寝る前に 0.55 秒の伸び(両手を上げるポーズ)を挟みました。
   4歳児には「寝た」より「眠そう」のほうが先に読めるためです。
5. **予備シーン A(あしあと)/ B(あめ)は採用していません**。§10-4 の通り Phase 2 末の判断事項で、
   本編 10 シーンの手触りを詰めるほうに時間を使いました。Phase 3 で再判断します。
6. `01.md` 本体は変更していません。

## 9. 既知の穴・Phase 3 へ

- **性能はまだ測っていません**。§9 の Phase 3 の課題(iPhone SE で 30fps 以上)はこれから。
  `fps()` フックは全シーンで読めます。
- **線のゆらぎ(ボイルド表現)** は §3 にありますが Phase 3 の項目のまま未実装です。
- E2E は `webkit` ではなくこの環境の Chromium で回しています。実機 Safari での確認は `npm run dev` + iPad(docs/02.md §6)。
- シーン1が指だけだと 30 秒前後かかります(44人を集めるので当然ではありますが)、通しの中では一番長い。
  Phase 3 で「集まりかけの塊がもっと強く吸い寄せる」調整の余地があります。
