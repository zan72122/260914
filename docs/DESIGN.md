# 星を起こす（Hoshi o Okosu）— 企画書 v1

対象: 4歳女児。iPhone / iPad、縦横両対応。一本指のみ。文字なし。失敗なし。制限時間なし。

## 0. コンセプト

**「石の中に眠っている光を起こす」**

一個の青い原石（スターサファイア）が、最初から最後まで **同じ石のまま** 変化し続ける。
向きを探し、固定し、削り、丸め、磨き、最後の曇りが消えた瞬間に六条のスターが目覚める。
完成後も終わらず、指で傾けるとスターが表面を滑る「遊べる完成品」になる。

ミニゲーム集ではない。画面に居るのは常にその一個の石であり、
加工履歴（削った場所・磨いた場所・固定した向き）は最後まで石の上に残る。

## 1. 石のモデル（identity の核）

`Stone` は 1 個のオブジェクト。全ステージがこれを読み書きする。作り直さない。

```
Stone {
  seed                // 原石ごとの乱数種（再プレイで変わる）
  params {            // seed から決定
    baseColor, depthColor      // 外側の青と内側の濃い青（例: 藍〜スカイ）
    silkDensity                // 内部の絹（ルチル針）模様の濃さ → 星の鋭さに影響
    starRays (6 | 12)          // 星の本数（稀に12条）
    starSharpness              // 光条の鋭さ
    roughShape                 // 原石形状の変形係数（凸凹の分布）
    cAxis (unit vec3)          // 星が出る軸。原石内で毎回ランダム
  }
  orientation (quaternion)    // 現在の向き。stage0 で回し、固定で確定
  grindMask   (texture R)     // 0=原石のまま 1=カボション形状まで削れた（UV毎）
  polishMask  (texture G)     // 0=曇り 1=鏡面（UV毎）
  windowMask  (texture B)     // 原石期に開けた「窓」（後述の固有動作）
  stage                        // 進行状態（下記）
}
```

形状はひとつのメッシュで、頂点ごとに `pos = mix(roughPos, cabochonPos, grindMask)` として連続変形する。
原石 → 粗形成 → カボションは **同じ頂点の morph** であり、別メッシュに差し替えない。
研磨は同じメッシュの roughness を polishMask で下げるだけ。
つまり石は一度も作り直されない。

## 2. 進行（自己駆動型の動作鎖）

各ステージは「前の操作の結果として、次に触る対象が自然に露出する」よう設計する。
説明テキスト・矢印・「次へ」ボタン・チュートリアル文は禁止。

### Stage 0: 原石（ころころ・のぞく）
- 画面: 暗い作業台に、宝石に見えないゴツゴツした青い原石が1個。ゆっくり自転してときどき光が走る（触りたくなる誘い）。
- **ドラッグ（石の上）= 石が転がる**（トラックボール回転）。
- 石の内部に `cAxis` があり、視線と cAxis の一致度 `align = dot(cAxis_world, viewDir)` で光帯の見え方が変わる。
  - align 低: 弱い光帯が 1 本、散らばって揺れる。
  - align 上昇: 光帯が 3 本に増え、中心へ集まり、星の気配（ぼやけた六条）になる。
  - align > 0.92 で「良い向き」: 石がふわっと脈打ち、低い持続音が鳴り、次の Stage 1 の誘いが現れる。
- **固有動作「窓開け」**（宝石職人の実際の手順）: 原石の一部をこすると、こすった場所だけ小さな平らな窓が開き、そこから内部の色と絹模様、光帯がはっきり見える。
  - こする = 小さな往復ドラッグ。指の通った場所の `windowMask` が上がり、その部分だけ透明度と反射が上がる。
  - 窓を通すと光帯の見え方が強まり、良い向きを探しやすくなる。窓は完成まで石に残る（削られて消えることもある＝履歴）。
  - 誘い: 原石の表面に一箇所だけ「薄皮」っぽく光が透けている場所があり、そこを触ると変化する。

### Stage 1: 固定（ぎゅっ）
- 良い向きに近づくと、画面の下（縦）／横（横）から **ドップ棒**（固定棒）がすっと現れ、先端の受け皿が石の底面と同じ形に光る（一致する形状）。
- 石の底（cAxis の反対側）が受け皿に向いて明滅し、受け皿も同じリズムで明滅する（対応関係）。
- **長押し（石の上）= 石が受け皿へ沈み込み固定される。** 押している間、指の周りにリングが満ちる。離すと戻る。満ちきると「カチッ」と音と振動で固定。
- 固定後、orientation は確定し、以後の回転操作はなくなる（触っても回らない＝固定されたことが体で分かる）。
- 誘い: ドップが小刻みに震え、受け皿が呼吸する。石が向きの近さに応じて受け皿に吸い寄せられる（磁石のような動き）。

### Stage 2: 粗形成（ガリガリ）
- 固定された石の横に **研削盤（回転砥石）** が出て回り始め、石の出っ張りに火花が散る（「出っ張りが邪魔」の可視化）。
- 石の周りに、目標形（カボション）の **ゴースト輪郭** が薄く重なる。輪郭からはみ出た出っ張りだけが淡く発光する（未完成の形）。
- **こする（石の上）= 指の通った場所がその場で削れる。** `grindMask` に指の軌跡を描き、その頂点が即座に cabochonPos へ寄る。火花・削り粉パーティクル・ガリガリ音（削る量に比例）。
- 出っ張りは多い順に消え、輪郭に収まった場所は発光が消える。全出っ張りの発光が消える（grindMask 平均 > 0.55 かつ最大凸部 < 閾値）と Stage 3 に連続移行。

### Stage 3: カボション化（ぐるぐる）
- 火花が水しぶきに変わり、砥石の回転音が柔らかくなる（同じ機械の細かい目に変わった表現）。
- 石はまだ角ばっている。ゴースト輪郭のドームだけが残って呼吸する。
- **こする（特に円を描く）= 石がドームへ丸くなる。** 同じ `grindMask` を 1.0 まで塗り切る。円運動だとストロークが連続しやすく自然に全周が塗れる。
- grindMask 平均 > 0.97 で形状完成。ゴースト輪郭が石と一致して溶けるように消える（一致 = 完了の合図）。
- この時点で石はドームだが表面は白く曇り、内部の星の気配が霞んで見える → 次の誘い。

### Stage 4: 研磨（つるつる）
- 研削盤が引っ込み、代わりに **磨き布／磨き皿** が現れる。石の表面はすりガラス状で、中の光が「出たがっている」ように脈打つ。
- **こする（石の上）= 指の通った場所から曇りが消える。** `polishMask` に軌跡を描き、その部分だけ鏡面になる。磨けた場所には星の一部が既に見える（部分的に星が出る＝続きを磨きたくなる）。
- 最後の曇りが消えた瞬間（polishMask 平均 > 0.985）: 画面が一瞬静まり → 六条のスターがパッと開く。チャイム、光の粒子、石が軽く跳ねる。

### Stage 5: 完成（遊べる完成品）
- ドップから外れて、石が台座の上に置かれる。
- **ドラッグ（画面のどこでも）= 石が傾き、スターが表面を滑らかに移動する。** 指が石を隠さないよう、画面のどこを触っても傾けられる。
- **タップ = 小さな煌めき**（星の交点から粒子が散る）。
- 完成した石は画面の端の **棚（コレクション）** に並ぶ。棚の石を見ると窓の跡や色の違いが分かる。
- 再プレイ: しばらくすると新しい原石が画面端から転がってきて止まる。それをドラッグで中央に引き込むと新しい `seed` の石で最初から。（完成石は棚に残る）

## 3. 操作語彙（一本指のみ）

| 操作 | どこで | 意味 |
|---|---|---|
| ドラッグ（大きく） | 石の上 (Stage 0) / どこでも (Stage 5) | 転がす・傾ける |
| こする（小さい往復） | 石の上 | 窓開け・削る・丸める・磨く（ステージで意味が変わるが指の動きは同じ） |
| 長押し | 石の上 (Stage 1) | 固定 |
| タップ | 石 | 煌めき（いつでも安全な操作） |
| ドラッグ | 新しい原石 (Stage 5) | 次の石を迎える |

ピンチ・二本指・精密操作・文字・タイマー・失敗・ゲームオーバー無し。
どのステージでも「触れば必ず何かがその場で変わる」ことを保証する。

## 4. ビジュアル方針

- Three.js（WebGL2、モバイル優先）。写実的な 2.5D〜3D。
- 石: 1 メッシュ + カスタム ShaderMaterial。
  - 外側の青 / 内側の濃い青（サブサーフェス風の深度色）
  - `roughness = mix(1.0, 0.05, polishMask)`、窓部分は先に低 roughness
  - 絹（silk）: cAxis 周りの筋模様を procedural に
  - **星（asterism）**: cAxis と視線・光源から計算。`rays` 本の光条を `|cos(rays/2 * θ)|^sharpness` で描き、中心はドーム上の光源反射点に置く。roughness が高いほど滲んで弱い。原石期は align に応じて光条が分離／収束する（3 本の帯として表示）。
  - 出っ張りは頂点変位（noise）。grindMask で cabochon 形状へ morph。
- 目標のゴースト輪郭: 同じ形状を線／薄いフレネルで描く。
- 機械（ドップ、砥石、磨き皿）はシンプルな形状 + 発光で「ここに石が来る」ことを形で示す。
- パーティクル: 火花、削り粉、水しぶき、光の粒。
- 縦画面: 石は画面中央より少し上、機械は下側。横画面: 石は中央、機械は右側。どちらも指が下から来ても星が隠れない配置。
- 画面回転／リサイズで `Stone` の状態は一切変えない（メモリ上で維持、さらに localStorage に保存して再読込にも耐える）。

## 5. 音（WebAudio 合成、素材ファイル無し）
- 原石が良い向きへ近づく: 低い持続音のピッチが上がる
- 固定: カチッ + 短い振動（navigator.vibrate があれば）
- 削る: ノイズ（削る量に比例）、火花のパチパチ
- 磨く: 柔らかいシュッ
- 星が開く: チャイム（和音）
- 完成品を傾ける: スターの動きに合わせた微かなきらめき音
- 最初のタッチで AudioContext を unlock。

## 6. 技術構成
- Vite + three（npm）。`npm run dev` / `npm run build` → `dist/` は静的ホスティング可能。
- `src/stone.js`（状態と morph）、`src/stoneMaterial.js`（shader）、`src/stages/*.js`、`src/input.js`（一本指ジェスチャー判定: tap / longpress / drag / rub）、`src/audio.js`、`src/layout.js`（縦横構図）、`src/machines.js`。
- デバッグ用に `window.__game` で stage / masks 平均 / align を読める（Playwright 検証用、UI には出さない）。
- Playwright（iPhone 縦・横ビューポート、touch）で一周自動試遊するスクリプト `scripts/playtest.mjs` と、各ステージのスクリーンショット出力。

## 7. 検証チェックリスト
1. 文字なしで、各ステージの「次に触る場所」が画面から分かるか（誘いの可視化）
2. 一本指だけで最後まで進めるか（Playwright の touch で自動一周）
3. 石の identity が途切れないか（同じメッシュ・同じ seed・masks が引き継がれる、窓の跡が残る）
4. 完成後のスターが指に追従して滑らかに動くか、何度も触りたくなるか
5. 縦横切替で状態が保持され、構図がそれぞれ自然か
6. iPhone 相当の性能で 60fps 近く出るか（頂点数・テクスチャサイズを抑える）
