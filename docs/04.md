## 1. 何を直したか(項目ごと)

### 1-1. シーン5 ちょうちょ — シグニファイアが見えなかった(レビュー指摘・最優先)

`butterfly-*-idle.png` で、ちょうちょは **子どもの頭と同じ大きさ・同じパステル・同じ高さ** にいました。
40 人の顔の中から「一匹だけいる生きもの」を見つけるのは、4歳児には不可能です。
シーンの誘い(§2.2)そのものが消えていたので、全面的に描き直しました。

| 直したこと | どこ |
|---|---|
| 色を **鮮やかな橙 + 山吹**、濃橙の **斑点模様**、子と同じこげ茶の輪郭線に | `src/art/palette.ts` / `src/art/props.ts` |
| 大きさを **頭の約2倍**(翼幅 約108世界単位。子の全高は150) | `props.ts` `drawButterfly` / `05_butterfly.ts` `BUTTERFLY_SCALE = 1` |
| **群衆より上のレイヤー**(`skyLayer`)に置き、深度ソートから完全に外した | `05_butterfly.ts` |
| 飛んでいる間、**薄い点線のクレヨン軌跡**(プール・リングバッファ、毎フレーム確保ゼロ) | `05_butterfly.ts` `updateTrail` / `props.ts` `drawTrailDot` |
| 群衆は **常に1体分下** に集まり(`CROWD_LAG = 250`)、ちょうの下に頭が入らない | `butterflyLogic.ts` |
| 全員が **顔を上げて** ちょうを見る(`attention` を世界側から常時 0.6 に保ち、体も傾ける) | `crowdScene.ts` の `tilt[]` / `05_butterfly.ts` |
| 人数を 34 → **28**、扇の広がりを 175 → 約300 にして顔の間に紙を作る | `05_butterfly.ts` |

「見えているか」は感想ではなく規則にしました。`butterflyLogic.clearsHeads()` が
「漂っている高さのちょうは、直下の子の頭より完全に上にいる」ことを表し、
`tests/butterfly.test.ts` が漂いの全周期でそれを検査します。

あわせて E2E のスクリーンショット。`butterfly-*-tap.png` は **次のシーン(すべり台)を撮っていました** —
通しプレイ用のジェスチャはシーンを終わらせるように書いてあるので、シャッターが下りる前にカメラがパンしていたためです。
撮影時だけ使う短いジェスチャ(`PHOTO_ROUND`、画面の 2/3 まで導いて離す)を足し、**追いかけの最中**を撮るようにしました。

### 1-2. シーン8 ふうせん — 縦長画面で横に流れて消えていた

`balloon-iphone-390x844-tap.png` では、浮いた子が **右端から** 出ていっていました。
iPhone の可視世界はちょうど 1000 単位角(= セーフゾーン)しかないので、
右寄りで浮いた子は上端に届く前に 500 単位以上流され、画面の横から出てしまいます。
このシーンで許される出口は **空だけ** です。

`balloonLogic.driftX()` が横位置を「端末が実際に見せている幅」の内側に丸めます(`DRIFT_SPEED` も 80 → 45)。
ゆれ(`swayOffset`)も同じ制限の内側です。もともと制限の外に立っていた子は **自分の位置がそのまま制限になる** ので、
浮き始めに横へ引き戻される不自然な動きは起きません。
`tests/balloon.test.ts` が、端末幅いっぱいに並んだ 26 人が上端に届くまでの全行程で一度も外へ出ないことを検査します。

### 1-3. 線のゆらぎ(ボイルド表現) — `01.md` §3 の積み残し

全ポーズ・全コマを **3通り焼き込み**(ゆらぎの種だけを変えた同じ絵)、群衆全体で **毎秒8回** 切り替えます。
ずれは1〜2pxなので「動いている」ではなく「手で描いた線が生きている」に見えます。

- 焼き込みは **同じアトラスの行を増やすだけ** です。ドローコールは増えず、毎フレームの追加処理は整数1個(`boilFrame(t)`)だけ。
- アトラスは 2688×768 → **2688×2304**(`window.__kids.atlas()` で確認。4096 制限の内側)。
  テクスチャメモリは約 8.3MB → 約 24.8MB。起動(ページ読み込み込み)はこの環境で約 310ms。
- `tests/boil.test.ts` は描画コードが実際にキャンバスへ置く座標を記録して、
  **3通りが本当に違うこと**と、**どの点も数px以上動かないこと**の両方を検査します。

### 1-4. BGM のスケジューリング

`setInterval` が鳴らしていた音を、Web Audio の **先読みスケジューリング**に置き換えました。
25ms ごとに起きる「ポンプ」が `audioContext.currentTime` を見て、100ms 以内に来る音を
**正確な時刻つきで** Web Audio に渡します。カーソルは1音ごとにちょうど1ステップだけ進むので、
タイマーが遅れても早くても2回続けて鳴っても、テンポは一切動きません
(以前は、40人が一斉に笑ってフレームが重くなるたびに音楽が引きずられていました)。

- クロスフェード API と、アンロック前のキュー動作はそのままです。
- 寝ていたタブ(ロックした iPad)は、欠けた分を **ステップ単位で飛ばして** 復帰します。1回の起床で32音以上は積みません。
- `scheduleDue()` は純関数で、`tests/audio.test.ts` が偽の音声クロックと **最大400ms遅れる**タイマーで駆動し、
  10分ぶんのシミュレーションで **ずれが厳密に0** であることを検査します(Pixi も AudioContext も使いません)。

### 1-5. 性能

`scripts/perf.mjs`(`npm run perf`)がビルド済みのゲームを電話サイズの Chromium で開き、
デバッグフック `window.__kids.stress(n)` で現在のシーンを n 体まで増やし、
ページ内の `requestAnimationFrame` で数えた実フレーム数と、CDP の `Performance` 指標、
強制GCを挟んだヒープ使用量を報告します。UI はありません(ゲーム自身は一度も呼びません)。

**この環境には GPU がありません**。Chromium は SwiftShader で WebGL を **CPU 描画**しています。
したがって以下の fps は **下限**であって、実機 iPhone の数字ではありません。

| 測定(iPhone 390×844 相当・シーン1・5秒窓) | 改善前 | 改善後 |
|---|---|---|
| 150体 fps(ページ内 rAF で実測) | 31.5 | **31.5** |
| 150体 JS 合計(シミュレーション + Pixi)| — | 壁時計の **1.3%** = 1フレームあたり約 0.42ms |
| 150体 ラスタライズ等(残り) | — | 壁時計の 99.8%(GPU がないため) |
| 150体 ヒープ(強制GC間、30秒) | **+776 KiB** | **−59 KiB** |
| 44体(素のシーン1) fps | — | 38.2 |
| 28体(シーン5)150体まで盛って fps | — | 33.1 |

ヒープは5回測って −213 / −59 / +109 / +142 / +234 KiB(40秒/30秒/10秒窓)。
この測定の揺らぎは ±250 KiB 程度なので **平ら** と読めます。
改善前は同じ条件で毎回きれいに増えていました(30秒で +566 / +776 KiB)。

**見つけた毎フレーム確保はすべて潰しました。**

- 空間ハッシュが `Map<number, number[]>` で、`length = 0` で空にすると配列のバッキングストアが縮み、
  翌フレームの `push` でまた伸びていました(150体×60fpsぶん、ゲームを開いている間ずっと)。
  いまは **Int32Array 3本**(開番地法のセル表 + 添字の連結リスト)で、クリアは世代カウンタの +1 だけです。
- 近傍クエリのコールバックを廃止(**毎フレーム・毎体1個のクロージャ**)。呼び出し側の使い回しバッファに書き込みます。
- 足音の効果音オプションのオブジェクトリテラルを使い回しに。

結果、ヒープは 30 秒で **+776 KiB → ほぼ平ら**になりました。

**ソートは今回ホットスポットではありません。** 150体でも JS 全部あわせて 1 フレームあたり約 0.45ms、
壁時計の 1.4% しか使っていません(残りはソフトウェアラスタライザ)。
`y` のしきい値や bucket ソートに置き換える根拠がないので、そのままにしてあります
(根拠が出たときのために、この判断を測定値とともにここに残します)。

### 1-6. シーン1 あつまれ の間合い

指だけで 32 秒(`docs/03.md` §7)かかっていて、通しの中で突出して長いシーンでした。
指を強くするのではなく、**集まりかけの塊に意味を持たせる**方向で直しています。
輪の中が **6割**を超えると、まだ外にいる子が自分からじわじわ引き寄せられ、
輪が埋まるほど強くなります(`gatherLogic.stragglerPull()`、減衰後の終端速度は歩く速さ以下)。

- しきい値未満では **完全に何も起きません**。29秒間まったく触らずに観測しても進捗は
  無操作ヒントぶんの 0.09 から動かず、**30秒の自動進行が唯一の無操作完了**のままです
  (E2E の `autoFired() === false` の検査もそのまま緑)。
- 同じ合成ジェスチャでの実測: **32秒 → 16.4秒**、その間 `autoFired()` は false。
- したがって `docs/03.md` §7 の「合成入力で通し115秒」はおおむね **100秒**になります。
  目標の「約5分・6分以内」に対しては引き続き余裕があります(合成入力は迷わず最短で触り続けるので、
  4歳児が実際に遊ぶともっと長くなります)。

### 1-7. PWA

画像ファイルはこのプロジェクトに1つもありません。アイコンも例外にしませんでした。
`src/art/icon.ts` が **ゲームと同じクレヨン関数・同じパレット**で、クリーム色の紙にわらう子の顔を描きます。
`scripts/make-icons.mjs`(`npm run icons`)がそのモジュールを esbuild で束ね、Chromium の本物の Canvas2D で走らせて
`public/icons/icon-{180,192,512}.png` を書き出します。

- `index.html` に `apple-touch-icon`(iOS はマニフェストではなくこちらを読みます)。
- `public/manifest.json` の `icons` を記入。`display` は `fullscreen` のまま。
- `tests/e2e/pwa.spec.ts` が **配信されているビルドに対して** 検査します:
  マニフェストが 200 で返る / 全面表示である / named されたアイコン URL がすべて本物の PNG として 200 で返る /
  `apple-touch-icon` も同様 / それでも画面は文字ゼロ。

## 2. デバッグフック(`window.__kids`)の追加分

画面には何も出ません。E2E とデバッグ専用です。

| フック | 返すもの |
|---|---|
| **`stress(n)`** | 現在のシーンを n 体まで増やし、増えたあとの総数を返す(性能測定専用) |

`stress()` が足す体は **別の群衆**に属します。そのため、どのシーンで呼んでも
そのシーンの持つ状態配列(風船の状態、茂みの割り当てなど)を壊しません。
一方で、1体あたりの負荷は本物の子と同じです — 同じ空間ハッシュ、同じポーズ状態機械、
同じスプライト書き込み、同じコンテナでの同じ深度ソート。
(逆に言うと、分離力は2つの群衆をまたいで働きません。負荷の測定としては誠実ですが、
シーンの見た目としては本来より少しばらけます。)

## 6. 既知の穴・残っていること

- **実機での fps は未計測です。** この環境は GPU なし(SwiftShader)なので、上の数字は下限です。
  `01.md` §7 の目標(iPad 60fps / iPhone SE 30fps)を主張するには、実機の Safari で
  `window.__kids.fps()` を読む必要があります。手順は §4 のとおりで、Safari の Web インスペクタから
  `__kids.stress(120)` と `__kids.fps()` を叩けばその場で測れます。
- **アトラスが約 24.8MB のテクスチャメモリを使います**(ボイル3通りのため3倍)。
  iPhone SE 2(3GB)では問題ない範囲ですが、それより古い端末を対象に加えるなら
  `BOIL_VARIANTS` を 2 に落とすのが最初の一手です(1行の定数です)。
- **E2E は webkit ではなくこの環境の Chromium で回しています。** 実機 Safari の確認は §4。
- **音は E2E では鳴っていません**(ヘッドレス Chromium に音声出力がなく、
  そもそもユーザー操作までアンロックされません)。スケジューラの正しさは単体テストで、
  例外が出ないことは E2E の `pageerror` 検査で担保しています。
- `stress()` が足す体は別群衆なので、分離力が本編の子とまたがりません(上記 §2)。
