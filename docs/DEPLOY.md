# 配信と実機（M4）

『ほんとうの火』を GitHub Pages で配り、iPhone / iPad のホーム画面から全画面で遊べるようにする。
設計の根拠は [PLAN.md](PLAN.md) §1・§3.6・§4。

## 1. 一度だけの設定（リポジトリの持ち主が手で行う）

GitHub の画面とローカルでの操作なので、ここだけは人がやる。

**1-1. 配信の定義を置く**

配信の定義は `docs/deploy/pages.yml` に置いてある。これを手元で所定の場所へ写して
コミットする。

```
mkdir -p .github/workflows
cp docs/deploy/pages.yml .github/workflows/pages.yml
git add .github/workflows/pages.yml
git commit -m "ci: GitHub Pages への配信"
git push
```

`.github/workflows/` に置くのを人の手でやるのは、この開発で使っている GitHub App が
`workflows` の権限を持たず、そこへのファイルを含む push が拒否されるため。
中身は写すだけでよく、書き換えるところは無い。

**1-2. Pages の配信元を切り替える**

1. リポジトリの **Settings** → 左の **Pages** を開く。
2. **Build and deployment** の **Source** を **GitHub Actions** にする
   （"Deploy from a branch" ではない）。
3. 保存する。以後、`.github/workflows/pages.yml` が配信する。

最初の配信は、1-1 の push が `claude/fervent-lamport-anoj0d` に載った時に走る。
**Actions** タブで `Pages` の走りを見られる。`build`（`npm ci` → `npm run test` → `npm run build`）が
通らなければ配信しない。手で走らせたいときは Actions から `Run workflow`。

配信の定義を直すときも `docs/deploy/pages.yml` を直し、同じように写し直す
（両方を揃えておく）。

## 2. 公開 URL

```
https://<GitHub のユーザー名>.github.io/260914/
```

リポジトリ名が URL の一段目に入るので、`vite.config.ts` の `base` を `'/260914/'` にしてある。
manifest・Service Worker・アイコンはすべてこの下に置かれる
（`e2e/pwa.spec.ts` が `vite preview` で同じ形を配って確かめている）。

リポジトリ名を変えたら `vite.config.ts` の `BASE` と `e2e/pwa.spec.ts` の `BASE` を揃えて変える。

## 3. iPhone / iPad のホーム画面に入れる

1. **Safari** で上の URL を開く（Chrome ではホーム画面追加の全画面が効かない）。
2. 下の共有ボタン（□に↑）をタップ。
3. **「ホーム画面に追加」** を選ぶ。
4. 名前は「ほんとうの火」のまま **追加**。
5. ホーム画面の炎のアイコンから開く。Safari の枠が出ず、全画面になる。

一度ふつうに開いておけば、Service Worker が資産を取り終えているので、
機内モードでも起動する。

## 4. 実機で確かめること

同梱の Chromium では確かめられない（＝実機でだけ分かる）ことを、この順で見る。

| # | 見ること | 手順 | 合格 |
|---|---|---|---|
| 1 | **音の解錠** | ホーム画面から開き、いきなり材料を指で押さえて炎へ引きずる | 最初の一本指の操作から、バーナーの「シュー」と炎に入る「ジュッ」が鳴る。二度目以降も鳴り続ける |
| 2 | **名前の声** | 困りが起きた瞬間と、正しく届けた瞬間 | 「どう〜」「ストロンチウム〜」「リチウム〜」と、届けたあと「〜、ありがとう」が ja-JP の声で鳴る。呼び声が重なっても順に鳴り、礼が呼び声に潰されない |
| 3 | **声が無い端末** | 設定 → アクセシビリティ → 読み上げコンテンツ の声を消した状態、または音声が用意されていない端末 | 無音のまま、遊びは最後まで成立する（名前が無くても届けられる） |
| 4 | **回転** | 材料を炎に入れて**指を離さないまま**端末を横にし、そのまま受け口へ運んで離す | 持っている材料が消えず、余熱の色も続き、横画面の受け口で仕事が動く。進行中の仕事も途切れない |
| 5 | **全画面** | ホーム画面のアイコンから開く | Safari のアドレスバー・下のバーが出ない。ノッチ／ホームインジケータの下まで世界が広がる（`viewport-fit=cover`） |
| 6 | **拡大・選択の抑止** | 画面を素早く二回叩く／二本指で広げる／長押しする | 拡大もしない、文字選択もメニューも出ない、上下に引っぱってもはね返らない |
| 7 | **オフライン起動** | 一度ふつうに遊んでからアプリを閉じ、機内モードにしてホーム画面から開く | 工房が立ち上がり、炎が燃え、遊べる |
| 8 | **画面に文字が無い** | 起動から数分、目で見る | 文字・ボタン・HUD・開始画面が一切出ない。名前は声だけ |
| 9 | **なめらかさ** | 炎の前で材料を往復させる | 指に付いてくる。炎の色が入れた瞬間に変わる |

## 5. 版を入れ替えたとき

`registerType: 'autoUpdate'` にしてあるので、新しい版が出ていれば次に開いたときに
黙って入れ替わる（利用者に何も出さない）。すぐ試したいときは、
ホーム画面のアプリを一度閉じてから開き直す。

それでも古いままなら、Safari の 設定 → Safari → 履歴とWebサイトデータを消去 で消えるが、
ホーム画面のアプリを削除して 3 章からやり直す方が早い。

## 6. 手元で配信と同じ形を見る

```
npm run build          # dist/ を作る（base = /260914/）
npm run preview        # http://127.0.0.1:4173/260914/ で配る
npx playwright test pwa.spec.ts   # manifest・SW・オフライン起動の検査
```

同じ Wi-Fi の iPhone から見たいときは `npx vite preview --host 0.0.0.0` にして、
`http://<PC の IP>:4173/260914/` を開く。
ただし Service Worker は `https` か `localhost` でしか動かないので、
オフライン起動と「ホーム画面に追加」の全画面は **Pages の URL でしか確かめられない**。
