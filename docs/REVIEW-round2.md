## 0. 結論（先に）

第1ラウンドで挙げた **高 2件（A・R）はいずれも解決**。中〜高の4件のうち3件（G・I・N）も解決。R1 の 25項目のうち **解決 18 / 部分 6 / 未検証 1（実機のセーフエリア）**、新規指摘 6件（うち中〜高 1件）。

## 3. 新たに見つかった問題（修正によるものを含む）

**新-1（中〜高・回帰の残り火）— 帰還の瞬間、棚用ミニジオラマが画面幅いっぱいに描かれる。**
`drawReturning()`（`src/scenes/hearth.js`）は `r = lerp(0.42*max(w,h), slot.r)` で `drawDiorama()` を呼ぶ。ミニジオラマは直径 60〜70px 用の絵なので、10倍に拡大すると
- ストロンチウム: 16本スポーク × `lineWidth = r*0.08` → 幅28pxの花弁12〜16枚の「ピンクの花」（`227/228-strontium-return-f00/f01.png`）
- バリウム: 同心リング＋太い縦棒が炉に重なる（`284-barium-return-f00.png`）
になる。リチウム・銅・ナトリウムは具象なので拡大しても意味が通る（`171-sodium-return-f01.png` は巨大な街灯で、むしろ気持ちよい）。
**最小の修正**: `drawReturning()` の開始半径を `0.42*max(w,h)` から `0.14*max(w,h)` 程度に下げ、`k<0.3` の間はミニジオラマを描かず**退出するワールド自身の引き**に任せる（アルファも `clamp((k-0.25)/0.3)` から立ち上げる）。あるいは `drawDiorama` に「これ以上大きくしない」上限 r を持たせる。

**新-2（中）— バリウムはタップの連打で半分進んでしまう。**
`TAP_MS = 120` は「押して離すまで120ms未満のみタップ扱い」。実測（`r2-run-probe.txt`）では 160ms 前後のよろけタップ8回で `turns01 = 0.494`。4歳児のタップは 150〜250ms が普通なので、この閾値では守れていない。
**最小の修正**: 時間ではなく**移動量**で判定する（`armed` を「押下点から `0.06*S` 以上動いた」ときに立てる）。指が動いていないのに角度が積まれることが無くなる。

**新-3（低）— 縦持ちで白いロープが炎を貫いて見える。**
ロープは炎の上から吊られ、対象皿（縦持ちでは画面中央〜右）へ斜めに垂れるので、`184-sodium-hearth-after.png`・`r2-probe/000-after-flame-taps.png` のように**炎の真ん中を縦断する**。iPad 横（`013-hearth-after-9s-idle.png`）では炎の右を通るので問題ない。
**最小の修正**: ロープの吊り元を炎の中心ではなく炎の**手前上（火皿の縁の上）**に置き、炎より奥（先に描く）にする。

**新-4（低・設計上の境界）— `spectroscope.js` が `hearth.js` を import している。**
`import { drawDiorama } from './hearth.js';`（意図はコメント済み: 棚と筒の絵を同一にするため）。DESIGN §5.4 は `worlds/*` 相互 import と `core→worlds/scenes` を禁じているのでルール違反ではないが、§7 の所有権境界（hearth=担当A、spectroscope=担当G）を跨ぐ依存になった。`drawDiorama` は共有描画なので、将来 `src/core/diorama.js` へ移すのが素直。

**新-5（低）— バリウムの滞在が 29.0s→40.5s に伸びた。**
設計内（30〜60s）だが、これは「迷いなく回した場合」の値。回すのに手間取る子では 60s を超え得る。`TURNS_REQUIRED` 据え置きのまま、デモ周回とクライマックス長が加算されたため。様子見でよい。

**新-6（低・QA の生命線に関わる）— 完了後も無効なヒットポイントが残る。**
`r2-run-engage.txt`: リチウムは挿入後も `fragment`（座標 x=-2311 = 画面外）と `slot` を返し続け、銅はクライマックス後も `trace:start` / `trace:end` を返す。DESIGN §5.10 は `hitPoints()` を「今押してほしい場所」と定義しているので、テストが「先頭の1件」を押すと空振りする（本レビューの自動プレイが実際にそれで銅の追加操作を取りこぼした）。R1 で指摘した「炎は `hitPoints()` に出るのに無反応」は解決したが、逆向きの不一致が残っている。
**最小の修正**: `lithium.js` / `copper.js` の `hitPoints()` で、`inserted` / `flow >= 0` のときは使えない id を返さない。

コンソールエラーは3デバイスすべてで **0件**（`r2-run-portrait.txt` ほか）。

## 6. 変えないでほしい所（第2ラウンドで特に良くなった点）

- **分光器に確実に辿り着ける**ようになったこと。掴めば必ず覗ける、という約束は4歳児向け設計として正しい。
- ロープ先のリングが**対象皿の色**で脈打つ合図。「炎 → ロープ → リング → この皿」が言葉なしで一直線につながる。
- 棚のミニジオラマ。走るローバー／灯る街／街灯が小さくても読めるので、収集欲が初めて機能する。
- バリウムの幕花火（横長）とストロンチウムの大輪（球）の形の対比。
- 音声タイミングは2ラウンド通して完璧。
