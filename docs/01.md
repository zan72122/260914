## 1. ゲームの核（何を遊ぶか）

Railbound と同じく **「客車を機関車まで届ける」** パズル。

- 盤面はグリッド（4×4 〜 7×7）。機関車（🚂）は右端付近の「おうち駅」に止まっている。
- 客車（🚃、犬が乗っている）が 1〜3 両、盤面のどこかに置かれ、番号の代わりに **色** で順番を示す。
- プレイヤーは空きマスに線路を置いて、客車が機関車まで転がる道を作る。
- 機関車をタップ → 客車が走り出し、順番どおりに機関車の後ろにカチャンと連結できればクリア。
- 客車同士がぶつかる / 線路が途切れて落ちる / 順番が違う → 失敗。ただし **失敗は「やり直しの合図」** であり罰ではない（後述）。

### 含めるメカニクス（小規模版）
1. 線路の配置・形の切り替え・削除（タップのみ）
2. 固定線路（灰色で最初から敷かれていて動かせない）
3. 客車 2〜3 両の **連結順**（色の順）
4. 衝突回避（2 両が同じマスに同時進入しない）
5. 岩・木などの障害物（線路が置けないマス）

### 含めない（将来の 02 以降）
トンネル、分岐スイッチ、踏切バリア、乗客の乗せ降ろし、坂道。

## 2. 「文字を読まなくてもわかる」設計 — Wordless interaction の具体策

原則: **説明の代わりに世界そのものが誘う**。テキストは一切表示しない（数字も含む）。

| 場面 | プレイヤーに起きてほしい行動 | 世界側の仕掛け（signifier / affordance / causality） |
|---|---|---|
| 初回起動 | 何かに触る | 画面中央の機関車が小さく上下に揺れ、煙をポフポフ吐く。タッチ可能なものは常に **わずかに動いている**。動かないものは触れない、という一貫ルール |
| 線路を置く | 空きマスをタップ | 空きマスは薄い土色の「路盤（枕木の跡）」として **未完成に見える**（perceptual incompleteness）。客車の進行方向の直後のマスだけ、点線の線路ゴーストがふわふわ点滅して「ここに置ける」と示す |
| 線路の形を変える | 同じマスを再タップ | タップ時に線路が「コトン」と回転して形が変わる（直線→カーブ4種→消える、の巡回）。物理的に「回す」動きで、次の形が予測できる |
| 線路を消す | 巡回の最後で消える（＝空きに戻る） | 消えるときは木片がパラッと散る。専用の削除ボタンは置かない |
| つながったか確認 | 見るだけ | 客車から機関車まで線路が途切れなく繋がると、線路が **順に淡く光り**、機関車が汽笛を1回鳴らして大きく揺れる（＝「押していいよ」）。途切れている端は線路がガタガタ震え、砂埃が立つ |
| 発車 | 機関車をタップ | 機関車を押すと沈み込み→ポッポー→煙→走り出す。ボタンではなく機関車本体が押し込める見た目 |
| 走行中 | 見守る | 客車がガタンゴトンと進む。速度は 1 マス/0.6 秒程度のゆっくり |
| 失敗（衝突） | もう一度やってみる | ぶつかると「ポヨン」と跳ね返り、犬が「？」の表情（吹き出しなし、目と耳だけ）。1 秒後に **巻き戻し演出**（映像が逆再生）で全員が元の位置へ。線路はそのまま残るので、直したい所だけ触り直せる |
| 失敗（線路の端で止まる） | 途切れ箇所を直す | 客車が端でコツンと止まり、その先の空きマスの線路ゴーストが強めに点滅。巻き戻しは同じ |
| 順番違い | 順番を直す | 色の順でカチャンと繋がる。違う色が来たら機関車がプイッと後ろを向いて拒否（連結せず押し返す）。機関車の後ろに **色の順番を示す「連結フック」** が並んでいる（赤・青・黄のリング）ので、見れば順がわかる |
| クリア | 次へ進む | 全員が連結すると汽笛・紙吹雪・犬たちが尻尾を振る。列車がそのまま画面右へ走り去り、画面が横スクロールして **ワールドマップ上の次の駅** に到着する。「次へ」ボタンは無い。列車自体が次の場所へ運ぶ |
| レベル選択 | 駅をタップ | ワールドマップは線路で繋がった駅の並び。クリア済みの駅は犬が手を振り、次の駅は機関車が煙を吐いて待っている。まだ行けない駅は霧の中（線路が途切れて見える） |
| もとに戻したい | 線路をタップし直す | Undo ボタンは置かない（4歳は「取り消し」概念を持たない）。直したいマスを触れば直る、が唯一のルール |
| 設定（音量など） | なし | 音の ON/OFF はデバイスのマナースイッチに委ねる。設定画面は作らない |

### 一貫ルール（3つだけ）
1. **動いているものは触れる**。止まっているものは触れない。
2. **触ると音と動きで即座に返事がある**（100ms 以内の視覚反応）。
3. **失敗しても何も失わない**。巻き戻して元に戻るだけ。

### 大人のための最小限の UI
- 右上に小さく 🏠（マップへ戻る）だけをアイコンで置く。これも常にわずかに揺れる。
- 押し間違いを防ぐため 1 秒長押しではなく、**タップでマップに戻るがレベルの線路は保持**（戻っても失うものがない）。

## 3. 画面・入力仕様（iPhone / iPad）

- **フルスクリーン PWA**: `manifest.json` + `apple-mobile-web-app-capable` + `viewport-fit=cover`。ホーム画面追加でアドレスバーなし。
- **縦横両対応**: Canvas はウィンドウ全体。盤面は常に `min(width, height)` に正方形でフィット。余白（縦なら上下、横なら左右）に空・雲・草原を描いて「世界の続き」に見せる。
- **回転時**: レイアウトを即再計算。状態は保持。
- **タップ判定**: 44pt 以上のマスサイズを保証（7×7 でも iPhone SE の短辺 375pt で 1 マス ≈ 50pt）。
- **誤タップ対策**:
  - ダブルタップズーム無効（`touch-action: none`）、長押しメニュー無効、選択無効。
  - 走行中は盤面タップを無視（機関車も含む）。巻き戻し完了後に受付再開。
- **セーフエリア**: `env(safe-area-inset-*)` を考慮して 🏠 アイコンを配置。
- **描画**: `devicePixelRatio` 対応で Retina でもくっきり。`requestAnimationFrame` ループ。
- **オフライン**: Service Worker で全アセット（HTML 1 枚 + manifest + アイコン）をキャッシュ。

## 4. ビジュアル方針

- 手描き風・コミック調（Railbound に寄せる）だが、**すべて Canvas のコードで描画**（画像アセットなし）。太い輪郭線＋やわらかい塗り。
- 客車の犬は 3 匹（赤・青・黄の首輪 = 連結順の色）。目・耳・尻尾だけで感情表現。
- 色は色覚多様性にも配慮し、色 + **形**（赤=丸、青=四角、黄=三角の荷札）で二重符号化。
- 線路の形は 6 種: 直線 2（縦・横）、カーブ 4（NE, NW, SE, SW）。タップ巡回順は「今の客車の向きから意味のある順」に並べ替える（例: 客車が右向きなら 横直線 → 右上カーブ → 右下カーブ → …）。

## 5. 音（Web Audio 合成）

| イベント | 音 |
|---|---|
| マスタップ（線路出現/回転） | 木のコトン（短い矩形波＋減衰） |
| 線路消去 | パラッ（ノイズバースト） |
| 全線つながった | やわらかい上昇 2 音 |
| 発車 | 汽笛（2 音和音の三角波、ビブラート）＋シュポシュポ（ノイズ） |
| 走行 | ガタン・ゴトン（マス境界ごとに低いノイズ） |
| 連結成功 | カチャン（金属的な短音） |
| 衝突 / 順番違い | ポヨン（下降するサイン波、怖くない音） |
| クリア | 3 音ファンファーレ＋汽笛 |

iOS の制約で音は最初のユーザー操作後に `AudioContext.resume()` で解錠する。無音でも完全に遊べる設計を維持。

## 6. レベル設計（12〜15 面・緩やかな難易度曲線）

各レベルは JSON リテラルで定義（グリッド、固定線路、障害物、客車の位置/向き/色、機関車の位置）。

| # | 盤面 | 客車 | 新しく学ぶこと |
|---|---|---|---|
| 1 | 4×4 | 1 | 空きマス 1 つを埋めるだけ（直線）。ゴーストが導く |
| 2 | 4×4 | 1 | 空きマス 2 つ（直線） |
| 3 | 4×4 | 1 | 初めてのカーブ 1 つ |
| 4 | 5×5 | 1 | カーブ 2 つで回り込む |
| 5 | 5×5 | 1 | 岩を避ける |
| 6 | 5×5 | 2 | 客車 2 両。同じ線路上に並んでいるので順番は自然に合う |
| 7 | 5×5 | 2 | 2 両が別方向から来る。合流（順番を色で合わせる） |
| 8 | 5×5 | 2 | 順番が逆になる罠。片方を遠回りさせる |
| 9 | 6×6 | 2 | 衝突を避けるタイミング（遠回りで時間差） |
| 10 | 6×6 | 2 | 固定線路をうまく使う |
| 11 | 6×6 | 3 | 3 両、3 方向から |
| 12 | 6×6 | 3 | 順番 + 衝突 |
| 13 | 7×7 | 3 | 総合（やや大人向け） |
| 14 | 7×7 | 3 | 総合 |
| 15 | 7×7 | 3 | 最終面。クリアで全員がおうちに着くエンディング演出 |

各レベルは実装前にシミュレータで **解が存在すること** と **1〜6 面は解が一意で単純であること** を自動検証する（後述のテスト）。

## 7. アーキテクチャ（ファイル構成）

```
index.html          … 1 ファイル。<canvas> と <script type="module"> のみ
src/
  main.js           … 起動、ループ、シーン切替（Map / Level）
  input.js          … Pointer Events → ゲーム座標への変換、走行中ロック
  render/
    board.js        … 盤面・線路・障害物の描画
    train.js        … 機関車/客車/犬の描画・アニメ
    fx.js           … 煙、紙吹雪、砂埃、巻き戻し
    map.js          … ワールドマップ描画
  sim/
    grid.js         … 線路の接続モデル（マスごとの出入り口）
    simulate.js     … 決定的な走行シミュレーション（tick 単位）。結果: 連結成功 / 衝突 / 脱線 / 順番違い
    solver.js       … テスト用: 解の存在確認（BFS/DFS）
  audio.js          … Web Audio 合成
  levels.js         … レベル定義
  storage.js        … localStorage（クリア状況・各レベルの線路配置）
  sw.js / manifest.json / icons/
tests/
  sim.test.js       … Node で実行する純粋ロジックのテスト（依存なし、`node --test`）
  levels.test.js    … 全レベルに解があることの検証
docs/
  01.md             … 本プラン
```

- `sim/` は DOM 非依存の純粋関数。描画はシミュレーション結果（tick ごとの位置列）を補間して再生するだけ。→ 「巻き戻し」は結果列を逆再生するだけで実装できる。
- 走行は **決定的**（乱数なし）なので、テストが安定。

## 8. シミュレーション仕様（要点）

- 1 tick = 各客車が 1 マス進む。全客車を同時に更新。
- 客車はマスの「入口」に対応する「出口」から次のマスへ。次のマスが線路でない/入口が合わない → **脱線停止**（失敗）。
- 同 tick に 2 両が同じマスに入る、または互いに入れ替わる（すれ違い）→ **衝突**（失敗）。
- 客車が機関車のマス（または既に連結した最後尾）に到達 → 色が期待順と一致すれば **連結**（以後は編成の一部として静止）。不一致 → **順番違い**（失敗）。
- 全客車が連結 → **クリア**。
- 最大 tick（例: 60）を超えたらループ判定で失敗。

## 9. テストと検証

- `node --test tests/` で純粋ロジック（接続判定・衝突・順番・脱線）を検証。
- 全レベルの解存在をソルバーで自動検証（CI 不要、ローカル実行）。
- 手動確認: Playwright + Chromium（同梱）で iPhone / iPad の縦横ビューポートをエミュレートしてスクリーンショットを撮り、レイアウト崩れがないことを確認。
- 実機確認は `python3 -m http.server` などで LAN 配信してもらう手順を README に記載（文字は README のみ、ゲーム内には無し）。
