# 01. Please Fix The Road 風ゲーム 企画・実装プラン

ステータス: 承認待ち(未実装)

## 1. 概要とゴール

### 1行で

4歳の女の子が、**文字をひとつも読まずに**、iPhone / iPad の Safari で遊べる、Three.js ローポリ 3D のタイルパズル。道を直して、車と列車を走らせる。

### 要約表

| 項目 | 内容 |
| --- | --- |
| 参照作品 | Steam「Please Fix The Road」 |
| 対象プレイヤー | 4歳の女の子(文字が読めない前提) |
| 最重要制約 | Wordless interaction(UI・ゲーム内に文字を一切出さない) |
| プラットフォーム | ブラウザのみ。iOS / iPadOS Safari。縦画面・横画面 両対応 |
| 描画 | Three.js / ローポリ 3D / 固定アイソメ(斜め見下ろし)/ 正射影 |
| 規模 | 3ツール × 10面 |
| ツール | 回転 / 上げ下げ / 破壊 |
| 乗り物 | 車、列車 |
| 配布 | 静的サイトのみ(PWA なし、Service Worker なし)。GitHub Pages |
| 音 | 効果音 + のんびりしたループ BGM。**人の声・言葉は一切なし** |
| 入力 | タッチのみ。1本指タップ中心。ドラッグ不要 |
| 実装 | 後日、監督者(Fable)の指示のもと Opus 5 が実施。**本書承認まで着手しない** |

### ゴール(達成条件)

1. 初回起動から、説明なし・文字なしで、4歳児が自力で1面をクリアできる。
2. 10面を通してツール3種の使い方が自然に身につく。
3. iPhone(縦)、iPad(横)の両方でレイアウト崩れ・誤タップがない。
4. 失敗しても叱られない。何度でもやり直せる。行き止まりの状態が存在しない。
5. `git push` だけで GitHub Pages に反映される。

### 非ゴール(今回やらないこと)

- オンライン機能、ランキング、セーブのクラウド同期
- レベルエディタ、ユーザー生成コンテンツ
- 文字によるチュートリアル、設定画面、オプションメニュー
- 外部の 3D モデルアセット / 音源ファイルの利用
- PWA / オフライン対応

## 2. 本家画像の分析

監督者が本家のプレイ画像5枚を精査した結果。デザインの拠り所とする。

### 2.1 砂漠面

- パレット: 橙〜黄の砂漠色。彩度は高いが眩しすぎない。
- タイルは**厚みのあるスラブ**。側面が見える。厚さはタイル幅の約 0.3。
- 道路タイル1枚がグリッドの上に**浮いている**。下に柔らかい影。
  → 「今このタイルを持ち上げて移動させている最中」という状態表現。
- 地面に**白い点線**がグリッド方向へ走る。移動可能なレール / スロットの提示。
- 白い円 + 4つの目盛(照準のような模様)がタイルに描かれる。→ **ゴール(到着地点)マーカー**。
- 装飾: 灯台のような塔、ヤシの木、枯れ草。

### 2.2 夜の線路面

- パレット: 濃紺〜ティール。夜。
- S字カーブの線路。赤い小型機関車 + 客車2両がスタート地点で待機。
- 装飾: 赤いレンガの塔、キノコ型の家、細長い暗い木、蛍のような光の粒。
- 2枚のタイルに**半透明の暗いオーバーレイ**+白い「**トレイに上矢印(⬆)**」アイコン。
  → 「持ち上げ」ツールの**適用範囲(2タイル同時)**を示す。
- **赤い細線**が線路沿いに走る。→ 経路プレビュー。

### 2.3 緑の都市面

- パレット: 夜の緑がかった色調。
- 窓の灯った高層ビル群、橙屋根の家、鉄柵と墓石の墓地。
- **黒い旗のポール** → ゴールマーカー。**黒い車** → スタート乗り物。
- 道路は灰色に白い縁取り。S字に公園タイルを通る。
- タイルに**高さの違い(段差)**。高いタイルは側面が厚く見え、低いタイルは沈む。
  → 段差を揃えないと道が繋がらない「上げ下げ」メカニクスの可視化。
- 左側に橙の線が走る線路。
- 草地には黄緑の背の高い葦、丸い塊状の木。

### 2.4 水面面

- 水色の水面に**コースティクス**(光の網目模様)。
- 緑の草タイルは水面より高く浮く(側面が見える)。
- 橋状の道路(灰色に白線)を**青いトラックが走行中**。→ 経路完成後の自動走行フィードバック。
- 赤黒の線が道路沿いに走る(経路インジケータ)。
- 装飾: 水面に黄色いアヒル、岩の岸、麦畑、赤い花の点列。

### 2.5 灰色の都市面

- 灰緑の都市。**横断歩道**のある道路。
- **2×2タイルの範囲**が点線枠 + 四隅の黒い丸で囲まれる。
- 半透明オーバーレイの上、各タイルに白い「**💣(丸い爆弾 + 導火線)**」アイコン。
  → 「破壊」ツールの**範囲選択(複数タイル同時)**。
- ビルや家がタイル上に乗る。ハイライトされたタイルには円形のパッド。

### 2.6 抽出した「見た目の文法」

本作でも必ず守る6つの視覚ルール。

| # | 文法 | 意味 | 本作での実装 |
| --- | --- | --- | --- |
| G1 | **タイルの厚み** | 地面ではなく「動かせる物体」 | 全タイルを厚さ 0.3 のスラブで描く。側面に暗めの色 |
| G2 | **浮きと影** | 今、操作されている / 動いている | 操作中タイルを +0.35 浮かせ、真下に柔らかい影 |
| G3 | **アイコン + 範囲表示** | このツールはここに効く | 半透明オーバーレイ + 点線枠 + 四隅の丸 + 白いアイコン |
| G4 | **ゴールマーカー** | ここに着きたい | 旗 or 円+目盛パッド。ゆっくり上下に揺れる |
| G5 | **経路プレビュー** | 道が繋がっている / いない | 道路・線路沿いに細線。繋がれば連続、切れれば途切れる |
| G6 | **自動走行** | 正解の報酬 | 経路完成で乗り物が自走。プレイヤーは見るだけ |

### 2.7 本家の骨格(そのまま踏襲)

> レベルごとに**配置済みの限定ツール**(範囲付きアイコン)をタップし、タイルを回転 / 上下 / 破壊 / 複製 / 入替 / 押して、A → B の経路を繋ぐ。繋がると乗り物が自動で走る。**失敗状態はなく**、いつでも試行錯誤できる。

本作は「複製 / 入替 / 押す」を削り、**回転 / 上げ下げ / 破壊** の3種に絞る。

## 3. Wordless 設計原則の適用

### 3.1 大原則

> Never explain an action when the world itself can invite it.
> 世界そのものを UI にする。思い出させるのではなく、見れば分かるようにする。

「4歳女児向け」= アニメ調やピンクにすることではない。**文字を読まなくてもわかる**こと。

### 3.2 文字ゼロを守る具体ルール

| 従来 UI | 本作での置き換え |
| --- | --- |
| タイトル画面「PRESS START」 | **タイトル画面なし**。起動即、世界が立ち上がる |
| レベル選択メニュー | **島を並べた地図**。島 = 1面。クリア済みの島は乗り物が走り続けている |
| 「ステージ1」などの番号 | 島の並び順と、島を結ぶ小道でのみ示す |
| チュートリアルテキスト | 1面の構成そのものが説明(回転1回で繋がる形に置く) |
| 「戻る」ボタン | **2本指ピンチアウト**で世界をズームアウト。加えて、常に少し見えている**隣の島や外側の海をタップ**しても地図へ戻る |
| 「リトライ」ボタン | 不要。常にやり直せる。状態が壊れないため |
| 設定・オプション | なし。音量は端末の物理ボタンに委ねる |
| 「クリア!」テキスト | 紙吹雪 + ファンファーレ + 島に旗が立つ |
| ローディング文言 | なし。アセットはコード生成なので即時 |
| エラー表示 | なし |

### 3.3 6つの認知原則への対応づけ

#### (1) Perceived affordance(知覚されたアフォーダンス)

- タイルは**厚いスラブ**として描き、地面から浮いて見える → 「つまめそう」。
- ツールアイコンは**丸い立体パッド**の上に乗る → 「押せそう」。
- 高いタイルの側面が見える → 「段がある / 上下しそう」。
- 触れないもの(装飾の木、家、山)は**平坦で地面と一体**に描き、影も薄い。

#### (2) Salient signifiers(目立つ意味手がかり)

- 操作可能タイルには常時、**白いアイコン**(⟳ 回転 / ⬆ 上げ下げ / 💣 破壊)。
- 適用範囲は**点線枠 + 四隅の黒い丸 + 半透明オーバーレイ**で囲む(本家 2.5 準拠)。
- 未操作のツールは**ゆっくり波打つハイライト**(1.5秒周期の明滅)で「触れる」と知らせる。
- 一度触ったツールは明滅を止める → 「もうわかったね」の合図。

#### (3) Familiar physical causality(なじみのある物理的因果)

- 回転: タップ → タイルが**実際に 90° くるっと回る**(0.25秒のイージング)。
- 上げ下げ: タップ → タイルが**ぐっと持ち上がる / 沈む**。土煙が少し出る。
- 破壊: タップ → **ぱっと砕けて破片が飛び**、跡が空地になる。
- どれも現実の「回す・持ち上げる・壊す」と同じ。説明不要。

#### (4) Natural mapping(自然な対応づけ)

- タップした場所 = 変化する場所(離れた場所のパネルを押させない)。
- 回転方向は常に**時計回り**で統一。予測が立つ。
- 高さは**見た目の高さそのもの**。数値やゲージは出さない。
- 画面上で左にある島は、地図でも左にある。

#### (5) Perceptual incompleteness(知覚的な未完成さ)

- **道が途中で切れている**状態を必ず作る。人は切れた線を繋ぎたくなる。
- 切れ目は画面中央寄りに置き、最初に目に入るようにする。
- 経路プレビュー線(G5)も**切れ目で途切れる**。どこが足りないか一目でわかる。
- 乗り物は出発点で**エンジンをかけて待っている**(排気・微振動)。完成待ちの気配。

#### (6) Immediate visual feedback(即時の視覚フィードバック)

- タップ後 **100ms 以内**に何かが必ず動く(押し込みアニメ + 効果音)。
- 経路が繋がった瞬間、プレビュー線が**端から端まで光が流れる**。
- 繋がらないタップでも「ぷにっ」と沈んで戻る → 「押せたけどまだ違う」。
- 乗り物が走り出す = 最大の報酬。ここまで無言で到達させる。

### 3.4 間違いを罰しない設計

- **失敗状態・ゲームオーバー・制限時間・手数制限を一切作らない。**
- 道が繋がっていないことは、通常は**経路プレビュー線の途切れ**だけで示す。毎タップで乗り物を走らせない(騒がしくなるため)。
- **6秒間無操作**のとき、ヒント演出を1回だけ行う: 乗り物が `path` 終端まで走り、止まり、車体が軽く傾いて(首をかしげる)短いクラクション1回。その後スタートへ戻る。責める音にはしない。
- 無操作ヒントを**2回出しても解けていなければ**、足りないタイルがそっと光る。文字は出さない。
- 正解時: 乗り物が走る → ゴールで**紙吹雪** → 短いファンファーレ → 自動で次の島へカメラが移動(ただし2秒間はタップで留まれる)。

## 4. コアメカニクス

### 4.1 グリッドとタイル

- 正方グリッド。1タイル = 1×1。厚さ 0.3。
- 各タイルは `height` 段階(0 / 1 の2段のみ)を持つ。段差 1 段 = 0.5。
- タイル種別:

| 種別 | 記号 | 接続方向 | 備考 |
| --- | --- | --- | --- |
| 直線 | `straight` | 相対する2方向 | 回転で縦横が切り替わる。水上では**橋バリアント**(橋げた付き)として描画。接続規則は同一で、違いは見た目だけ |
| カーブ | `curve` | 隣接する2方向 | 回転で4向き |
| T字 | `tee` | 3方向 | 回転で4向き |
| 十字 | `cross` | 4方向 | 回転しても見た目同じ(回転対象外) |
| 空地 | `empty` | なし | 草 / 砂 / 水。通行不可 |
| 障害物 | `block` | なし | 岩、廃屋など。破壊対象 |
| 始点 | `start` | 1方向 | 乗り物が置かれる |
| 終点 | `goal` | 1方向 | ゴールマーカー |

- **道路**と**線路**は別レイヤーの種別。互いに接続しない。交差は立体交差として描画。
- 1つのタイルは「道路 or 線路 or 空地 or 障害物」のいずれか1つ。

### 4.2 ツール3種(厳密定義)

本家同様、ツールは**レベルごとに盤面へ配置済み**。個数・位置・適用範囲はレベルデータで固定。プレイヤーはツールアイコンをタップして発動する。ツールを動かしたり選んだりはしない。

#### T1. 回転(⟳)

- 適用範囲: 1タイル(基本)。レベルにより 1×2 / 2×2 も可。
- 挙動: **タップするたび 90° 時計回り**。範囲内の全タイルが同時に回る。
- 回転しても種別・高さは変わらない。接続方向だけが回る。
- 使用回数制限なし。何度でも回せる(360° で元に戻る)。
- アニメ: 0.25 秒 ease-out。回転中は入力を受け付けない。
- 音: 軽い「カチッ」。

#### T2. 上げ下げ(⬆)

- 適用範囲: 1〜4タイル(本家 2.2 は2タイル同時)。
- 挙動: **タップで高さをトグル(0 ⇄ 1)**。段階は2つのみ。循環は導入しない(4歳児には予測が難しいため)。
- 範囲内タイルは**同じ段数だけ**一斉に動く(相対差は保つ)。
- **接続条件に高さが関わる**: 隣接する2タイルは、高さが等しいときのみ接続する。
  - 例外: 傾斜タイル `slope` は導入しない(4歳には複雑すぎる)。
- アニメ: 0.3 秒。持ち上げ時に土煙パーティクル。
- 音: 「ズズッ」と低い摩擦音 + 着地の「トン」。

#### T3. 破壊(💣)

- 適用範囲: 1〜4タイル(本家 2.5 は 2×2)。
- 挙動: **タップで範囲内の障害物(`block`)を消して空地にする**。
- **破壊対象は `block` のみ**。道路・線路タイル、`start` / `goal`、地形の地面は破壊できず、範囲内に含まれていても「ぷにっ」と沈んで戻るだけ。道を失う操作が存在しないので「壊して詰む」が**原理的に起きない**。
- **使い切り**: 1回使うとそのツールは消える(点線枠ごと消える)。
- アニメ: 0.4 秒。破片が飛び、土煙。
- 音: 「ポン!」という軽い破裂音。爆発音にはしない(怖くないように)。

#### ツールの共通表示(本家準拠)

- 適用範囲に**半透明の暗いオーバーレイ**(不透明度 0.25)。
- 範囲の外周に**白い点線枠**。四隅に**黒い丸**。
- 範囲内の各タイル中央に**白いアイコン**。
- 未使用ツールは 1.5 秒周期でオーバーレイの明度が波打つ。

### 4.3 経路判定アルゴリズム

純関数として実装。副作用なし。単体テスト対象。

```
solve(board) -> { connected: boolean, path: Tile[] }

1. start タイルを見つける。
2. 幅優先探索(BFS)を行う。
3. タイル A から隣接タイル B へ進めるのは、次を全て満たすとき:
   a. A の接続方向集合に「B の向き」が含まれる
   b. B の接続方向集合に「A の向き」が含まれる   (双方向の握手)
   c. A.height === B.height                      (段差なし)
   d. A.layer === B.layer                        (道路同士 / 線路同士)
4. goal に到達したら connected = true。経路を復元して path とする。
5. 到達しなければ connected = false、path は start から進める最遠点までの経路。
```

- 判定はツール操作の**たびに即時実行**(盤面は最大 7×7 = 49 タイル。コストは無視できる)。
- `connected === false` のとき、`path` の終端が「乗り物が止まる場所」になる。
- 経路プレビュー線は `path` に沿って描画する。つまり**プレビュー線が途切れる場所 = 足りない場所**。

### 4.4 乗り物の走行と到着判定

- 経路が繋がると**自動で**発車(プレイヤー操作不要)。0.5 秒の溜めを置いてから動き出す。
- 速度: 1タイルあたり 0.6 秒。カーブでは車体が傾く。
- 列車は先頭 + 客車2両。後続は先頭の軌跡を遅延追従。
- ゴールタイルに到達 → 停止 → 紙吹雪 → ファンファーレ → クリア確定。
- 途切れている場合: 通常は**走らせない**。経路プレビュー線の途切れで示す(3.4)。
  - **6秒間無操作**のときのみヒントとして `path` 終端まで走り、停止し、首をかしげてクラクション1回。その後**自動でスタート地点に戻る**(1.5秒)。何度でも再挑戦できる。
- 走行中もツール操作は可能。操作された瞬間、乗り物はスタートへ戻ってやり直す。

### 4.5 状態と進行

- 進行状況(どの島をクリアしたか)は `localStorage` に保存。キーは1つだけ。
- 保存に失敗しても遊べる(try/catch で握りつぶす)。
- リセット手段は UI に出さない(4歳児が誤って消さないため)。

## 5. 操作と画面

### 5.1 入力

| 操作 | 割り当て |
| --- | --- |
| 1本指タップ | ツール発動 / 島に入る / 盤面の外側(海・隣の島)をタップして地図へ戻る |
| 2本指ピンチアウト | ズームアウト。プレイ画面では地図へ戻る主操作 |
| 2本指ピンチイン | 地図画面で島に寄る |
| その他 | 割り当てなし |

- **ドラッグ不要**。4歳児はドラッグの精度が低い。
- **長押し不要**。
- **ダブルタップ禁止**: `touch-action: none` + `user-scalable=no` でブラウザのダブルタップズーム・ピンチズームを無効化。
- ブラウザのズームは殺すが、**ピンチ自体は pointer イベントを自前で処理して検出**する(2点の距離変化を追う)。判定は緩め: 距離が 1.2 倍以上でズームアウトとみなす。
- タップ判定は `pointerdown` ではなく `pointerup` で確定。ただし押下時に即座に押し込みアニメを出す(3.3-(6))。
- 移動距離が 12px を超えたら「タップではない」としてキャンセル(誤スワイプ耐性)。

### 5.2 当たり判定(4歳の指を考慮)

- ツールアイコンの当たり判定は**見た目の 1.4 倍**。
- 隣接ツール同士は最低 **48 CSS px** 離す(実寸で約 8mm 以上)。
- Three.js の Raycaster は、アイコンごとに**見えない大きめの板(invisible plane)**を当たり判定用に置く。
- 画面端から 16px 以内はタップを無視(手のひらの誤接触対策)。

### 5.3 カメラ

- **正射影カメラ**(`OrthographicCamera`)。固定アイソメ。
- 回転・自由視点は**なし**(4歳児が迷子にならないため)。
- 盤面のバウンディングボックスを計算し、**縦横どちらでも全体が収まる**ように `zoom` を自動調整。
  - 縦画面: 横幅基準でフィット。上下に余白。
  - 横画面: 縦幅基準でフィット。左右に余白。
  - 余白は最低 15%。**この余白には必ず、隣の島の端と外側の海が少し覗く**ようにする。
    - 狙い: perceptual incompleteness =「向こうにまだ世界がある」。覗いている隣の島 / 海をタップすると地図へ戻る(5.1)ため、戻る操作の発見可能性も上がる。
- `resize` / `orientationchange` でフィットを再計算(デバウンス 150ms)。

### 5.4 レイアウトと safe area

- キャンバスは全画面。HTML の UI 要素は**置かない**(文字がないので DOM UI が不要)。
- `viewport-fit=cover` + `env(safe-area-inset-*)` を考慮し、**インセット内側にだけ**操作対象を配置。
  - iPhone のノッチ / ホームインジケータ領域にツールが来ないよう、フィット計算に安全余白を足す。
- `overscroll-behavior: none`、`position: fixed` でバウンススクロールを抑止。
- アドレスバーの伸縮対策に `100dvh` を使用。

### 5.5 画面構成(全2画面)

1. **地図画面**: 海に浮かぶ10個の島。小道で繋がる。クリア済みの島では乗り物が周回している。島をタップで入る。
   - **10面すべてクリア後**: 全島で乗り物が走り、旗が立ち、花火が上がる**祝祭状態**になる(これがエンディング。別画面は作らない)。
2. **プレイ画面**: 盤面。周囲に隣の島と海が少し覗く。ピンチアウト、または覗いている隣の島 / 海をタップすると地図へズームアウトして戻る。

これ以外の画面は作らない。

## 6. レベル設計

### 6.1 難易度曲線の方針

- 1〜2面: **1操作で繋がる**。因果を教える。
- 3〜5面: ツールを1種ずつ追加。組み合わせはまだ無し。
- 6〜8面: ツール2種の組み合わせ。範囲ツール(複数タイル同時)を導入。
- 9〜10面: 3種同時。ただし手数は最大でも 6 操作程度に抑える。
- **どの面も、正解手数は最大 6 操作**。総プレイ時間の目安は 15〜25 分。
- **グリッドは最大 7×7**(縦画面の視認性のため)。**乗り物は常に1台**(複数経路を同時に扱わせない)。

### 6.4 レベル1の具体設計(チュートリアル代わり)

- 4×4。左上に `start`(車)、右下に `goal`(旗)。
- 道は 1 枚のカーブタイルだけが**間違った向き**で置かれている。
- そのタイルにだけ回転ツール(⟳、明滅あり)が乗っている。他に触れるものはない。
- 経路プレビュー線が、そのタイルの手前で**ぷつりと切れている**。
- 車はエンジン音を立てて待っている。
- → 4歳児の視線: 動くもの(明滅) → タップ → 回る → 線が繋がる → 車が走る。**説明ゼロで完結**。

## 7. 見た目と音

### 7.1 パレット

すべて本家画像から採取した方向性。彩度はやや高め、明度差は大きめ(4歳児の視認性)。

| テーマ | 地面 | 道路 | アクセント | 空/背景 |
| --- | --- | --- | --- | --- |
| 砂漠(昼) | `#E8B454` | `#8C8378` + 白縁 | `#F2E3B0` | `#F6D28A` |
| 砂漠(夕) | `#D9884A` 系の橙赤 | 同上 | `#FFD9A0` | `#E87A55` |
| 草原 | `#7CBF5A` | 灰 + 白縁 | `#C8E89A` | `#9FD9F0` |
| 水辺 | `#5FC8D8`(水) / `#78C86A`(草) | 灰 + 白線 | `#F2D857`(アヒル) | `#BEE8F2` |
| 灰色の都市 | `#96A08C` | `#6E6E6E` + 横断歩道白 | `#C4C9BC` | `#AEB8A8` |
| 緑の都市(夜) | `#2E4A3A` | `#4A4A4A` + 白縁 | 窓の灯 `#F5D77A` | `#16283A` |
| 夜の線路 | `#1E3A4C` | 線路 `#5A4A3E` | 蛍 `#BFF7A8` | `#14202E` |

- タイル**側面**は上面より約 20% 暗くする(厚みの知覚・G1)。
- 色だけに意味を持たせない(7.6 参照)。

### 7.2 モデリング方針

- **外部アセットを一切使わない。すべてコードでプロシージャル生成。**
  - 理由: ライセンス、ロード時間、GitHub Pages のサイズ、差し替えコスト。
- 使うジオメトリ: `BoxGeometry` / `CylinderGeometry` / `ConeGeometry` / `SphereGeometry` / `ExtrudeGeometry` の組み合わせ。
- 例:
  - 木 = 円柱(幹) + 球 or 円錐(葉)
  - 家 = 箱 + 三角柱(屋根)
  - 車 = 箱2つ + 円柱4つ(車輪)
  - 列車 = 箱 + 円柱(煙突) + 客車の箱
  - 灯台 = 円柱 + 円錐 + 小さな球(光)
  - アヒル = 球 + 小球 + 小円錐(くちばし)
- マテリアルは `MeshLambertMaterial` を基本(軽い / トゥーン寄りの見た目)。
- 道路の白線・横断歩道・ゴールの円+目盛は、**CanvasTexture で描いた小さなテクスチャ**をタイル上面に貼る。
- **ツールアイコン(⟳ / ⬆ / 💣)も絵文字フォントを使わず、CanvasTexture 上に図形として描画する。**
  - 理由: 絵文字は OS / フォントで見た目が変わり意味が安定しない。また DOM にテキストを置かないので 8.6 の「テキストノード0」テストと整合する。
  - 描き方: 回転 = 円弧 + 三角の矢尻。上げ下げ = 台形のトレイ + 上向き太矢印。破壊 = 円 + 導火線 + 火花。すべて `CanvasRenderingContext2D` のパスで描く。

### 7.3 ライティングと影

- `HemisphereLight`(空色 + 地面色)+ `DirectionalLight`(1灯、影キャスト)。
- シャドウマップは 1024×1024。正射影カメラのシャドウフラスタムを盤面にぴったり合わせる。
- 操作中タイルの影は、**別の薄い円形メッシュ**を真下に置いて表現(シャドウマップより確実で軽い)。
- 夜の面では `DirectionalLight` を弱め、窓・蛍を `MeshBasicMaterial` の発光色で表現。

### 7.4 アニメーション

| 対象 | 時間 | イージング |
| --- | --- | --- |
| タイル回転 | 0.25s | ease-out |
| タイル上下 | 0.30s | ease-in-out + 着地時に微バウンス |
| タイル破壊 | 0.40s | 破片は重力落下 |
| ツール明滅 | 1.5s 周期 | sine |
| ゴールマーカー上下 | 2.0s 周期 | sine、振幅 0.1 |
| 経路プレビューの光 | 0.8s | 端から端へ流れる |
| 乗り物 1タイル | 0.60s | 等速 + カーブで傾き |
| カメラ移動(島↔盤面) | 0.8s | ease-in-out |

### 7.5 音

- **外部音源ファイルを一切使わない。すべて Web Audio API で合成。**(ライセンス回避 + 軽量)
- **人の声・言葉は一切なし。**

| 音 | 合成方法 |
| --- | --- |
| 回転 | 短い矩形波 + 急減衰(カチッ) |
| 上下 | ノイズ + ローパスのスイープ(ズズッ)+ 低音の「トン」 |
| 破壊 | ノイズバースト + 帯域ノイズ(ポン!)。低音は控えめ = 怖くない |
| タップ失敗 | 短い低め正弦波1発(責めない) |
| クラクション | 三角波 2音の和音、0.3秒、1回だけ |
| 走行音 | 低音の正弦波をゆらぎ付きで持続。列車は「シュッシュッ」のノイズ周期 |
| ファンファーレ | 三角波でペンタトニック上昇 4〜5音 |
| 紙吹雪 | 高音のキラキラ(短い正弦波を乱数ピッチで複数) |

- **BGM**: のんびりしたループ。合成で生成。
  - ペンタトニック音階、テンポ 72〜84 BPM、三角波 + 柔らかいディレイ。
  - 4〜8小節をループ。テーマごとに音色とキーを変える(砂漠 = 明るい、夜 = 落ち着いた低め)。
  - 音量は控えめ(効果音の 40% 程度)。
  - **オン/オフ UI は設けない**(文字なし UI を増やさないため)。音量は端末の物理ボタンに委ねる。
- **iOS 対策**: `AudioContext` は**最初のタップで `resume()`**(10章参照)。

### 7.6 色覚多様性・視認性への配慮

- 「繋がっている / いない」を**色だけで示さない**。線の連続 / 途切れという**形**で示す。
- ツールの識別は**アイコンの形**(⟳ / ⬆ / 💣)で行う。色は補助。
- 上面と側面のコントラスト比を十分に取り、段差を明度で読めるようにする。

### 8.4 状態管理

- グローバルなミュータブル状態を持たない。
- `applyTool(board, toolIndex) -> newBoard` の**純関数**。
- 描画層は「新しい board を受け取って差分を反映する」だけ。
- 履歴(undo)は board のスナップショット配列で実現可能だが、**今回は実装しない**(4歳児に undo の概念は不要。やり直しは常時可能)。

### 8.5 GitHub Pages 用ビルド

- `vite.config.ts` の `base` をリポジトリ名に設定(例: `base: '/260914/'`)。
- 出力先は `dist/`。GitHub Actions で `main` への push 時にビルド → Pages へデプロイ。
- **Service Worker は作らない。PWA マニフェストも置かない。**
- アセットが無いため `dist/` は JS + HTML のみ。数百 KB に収まる見込み。

### 8.6 自動テスト

| 種別 | 内容 |
| --- | --- |
| 単体(Vitest) | `solve` の経路判定: 繋がる/繋がらない/段差/レイヤー違いの各ケース |
| 単体(Vitest) | `tools`: 回転 4 回で元に戻る、上下のトグル(0⇄1)、破壊は `block` にのみ効き道路は残る |
| 単体(Vitest) | 全10面が解けること、かつ**初期状態では解けていない**こと |
| E2E(Playwright) | iPhone 縦 / iPhone 横 / iPad 縦 / iPad 横 の 4 ビューポートでスクリーンショット |
| E2E(Playwright) | レベル1を実際にタップしてクリアできること |
| E2E(Playwright) | 画面内に**テキストノードが存在しない**ことの検証(Wordless の自動保証) |

- 最後の「テキストノード0」テストは、本企画の最重要制約を機械的に守るための番人とする。

- パフォーマンス確認(iPhone 実機で 60fps、発熱しないこと)。
- **実際に4歳児に遊んでもらい**、詰まった箇所を記録して修正。
- **完了条件**: 4歳児がひとりで少なくとも 5 面をクリアできる。E2E 全緑。

## 10. リスクと未決事項

### 10.1 リスク

| # | リスク | 対策 |
| --- | --- | --- |
| R1 | **iOS のオーディオ自動再生制限** | `AudioContext` を最初のユーザータップで `resume()`。BGM もそのタップ後に開始。地図画面の最初の島タップが必ずその契機になる設計 |
| R2 | iOS Safari でタブ復帰時に `AudioContext` が suspended になる | `visibilitychange` で resume を再試行 |
| R3 | WebGL コンテキストロスト(バックグラウンド復帰時) | `webglcontextlost` / `restored` を監視し、シーンを再構築 |
| R4 | パフォーマンス(古い iPad) | メッシュ数を抑える。同種プロップは `InstancedMesh`。影は 1 灯のみ。`pixelRatio` を最大 2 に制限 |
| R5 | 発熱・バッテリー | 60fps 上限。アニメが無いフレームは再描画しない(オンデマンドレンダリング) |
| R6 | 色覚多様性 | 形で意味を示す(7.6)。色だけの区別を作らない |
| R7 | 4歳児がツールを見つけられない | 明滅ハイライト。3秒触られなければ明滅を強める。6秒無操作で乗り物のヒント走行(3.4)、それを2回経ても未解決なら足りないタイルが光る |
| R8 | 誤タップで意図しない操作 | 当たり判定の間隔を 48px 以上。破壊以外は全操作が可逆。破壊も `block` を消すだけで経路を壊さない |
| R9 | 破壊ツールで詰む | **破壊対象を `block` のみに限定**したため原理的に発生しない。道路・線路は壊せず、経路が失われる操作が存在しない |
| R10 | GitHub Pages の `base` パス設定ミスで真っ白 | M1 でデプロイ経路を最初に確立する |
| R11 | 文字が紛れ込む | Playwright の「テキストノード0」テストで機械的に防ぐ |
| R12 | 4歳児が長時間遊びすぎる | 今回は対策しない(保護者に委ねる)。要検討事項として残す |
