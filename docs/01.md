## 1. 設計原則: Wordless interaction を世界の仕組みで実現する

「文字を読まなくてもわかる」ために、次の 6 つを画面上の具体物に落とし込む。画面には文字・数字・アイコン付きボタンを **一切置かない**。

| 原則 | 本作での具体化 |
|---|---|
| **Perceived affordance**(見れば触りたくなる) | 楽器は箱の中で小さく跳ねて「持ち上げられる」ことを示す。汽車は最初から蒸気を吐いて「動きたがっている」 |
| **Salient signifier**(次の場所が目立つ) | 線路脇の空きスロットは「へこんだ影付きの空き穴」。楽器を持ち上げた瞬間だけ穴が明るく脈打つ |
| **Familiar physical causality**(見慣れた因果) | 汽車が楽器に当たる → 楽器が揺れる → 音が出る。同時に起きるので因果が一目でわかる |
| **Natural mapping**(自然な対応) | 高い場所 = 高い音。速い汽車 = 速いテンポ。右へ進む = 次へ。汽車の後ろに増える貨車 = 重ねた曲の数 |
| **Perceptual incompleteness**(足りないものを埋めたくなる) | 空の穴、閉じたトンネルの扉、空の貨車。「埋めれば何か起きる」ことを形で示す |
| **Immediate visual feedback**(即時反応) | 触った瞬間に必ず音+動きで応える(持ち上げた楽器はその音を一度鳴らす、置くと着地でぽよんと弾む) |

補足ルール:
- **失敗状態を作らない**。どこに置いても、どの組み合わせでも音楽として破綻しないよう、音階をペンタトニックに固定し、拍を線路の枕木に量子化する。
- **取り消しは「戻す」動作で**。楽器を穴から持ち上げて離せば、箱へぴょんと帰る(ゴミ箱アイコンなどは置かない)。
- **待たせない**。読み込み・状態遷移中も汽車は動き続ける(ローディング画面なし)。
- **誤タップに強い**。ダブルタップズーム・スクロール・長押しメニューを無効化。小さい指で掴めるよう当たり判定は見た目より大きく(最小 64px)。

## 2. プレイ体験(画面ごとの流れ)

### 2.1 起動直後(音のアンロック)
iOS では最初のタッチまで音が出せない。そこで:
- 画面中央に汽車が停まっており、**煙突から蒸気が「ぽっ、ぽっ」と出て小さく揺れている**(触りたくなる)。
- 画面のどこを触っても AudioContext を開始し、汽車が汽笛を鳴らして走り出す。
- 文字での案内はなし。汽車が唯一動いているものなので、そこに注意が向く。

### 2.2 レベル(ジオラマ 1 枚)
- 画面いっぱいの**紙のジオラマ**。楕円の線路がループしている(ループ 1 周 = 2 小節 = 8 拍)。
- 線路には **8 本の太い枕木**があり、各枕木の外側に**楽器を置く穴**が 1 つずつある(計 8 穴)。
- 画面の端に**おもちゃ箱**があり、そのレベルで使える楽器が 3〜4 種類入っている(縦画面では下、横画面では右)。
- 楽器は箱の中で時々小さく跳ねる。触ると持ち上がり、その楽器の音が一度鳴る。
- 持ち上げている間、空いている穴が明るく脈打つ。穴の上で離すと着地して弾み、汽車が通るたびに鳴る。
- 汽車が楽器を通過する瞬間: 楽器がぷるんと揺れ、音符の代わりに**色のついた紙吹雪(1〜2 枚)**が舞う。
- 穴以外の場所で離すと、楽器は箱へぴょんと戻る(=取り消し)。
- 同じ楽器は箱から何個でも出せる(箱の中の楽器は「無限にある見本」)。

#### 音の高さ(メロディ楽器のみ)
- メロディ系楽器(とり、すず、ふえ)は、穴に置くと**支柱(ポール)の上に乗る**。
- 楽器を上下にドラッグするとポールが伸び縮みし、**高いほど高い音**が鳴る(ドラッグ中もリアルタイムで鳴る)。5 段階(ペンタトニック 5 音)。
- ドラム系(たいこ、かすたねっと、しゃかしゃか)はポールなし、地面に置くだけ。

#### テンポ
- 汽車の**運転席の石炭スコップ**をタップすると火が大きくなり、汽車が少し速くなる(3 段階でループ)。火の大きさ = 速さ。
- v1 では 3 段階(ゆっくり・ふつう・はやい)。

### 2.3 次のレベルへ(重ね録り)
- 線路の右端(横画面)/上端(縦画面)に**トンネルの扉**がある。最初は閉じている。
- 楽器を 1 つ以上置くと、扉が**少し開いて中から光が漏れる**(perceptual incompleteness)。
- 扉をタップすると全開になり、次にその前を通った汽車がトンネルへ入る。
  - このとき、置いた楽器たちは**ぴょんぴょんと飛び上がって新しい貨車に乗り込む**(見て「今の曲を持っていく」とわかる)。
- 画面が横にスクロールし、次のジオラマ(別の色・季節・別の楽器セット)が現れる。汽車は貨車を 1 両引いて登場し、**貨車の楽器は鳴り続けている**。
- 新しいレベルで同じように楽器を置くと、前の層に重なって聞こえる。
- 貨車は最大 3 両(= 4 層)。4 層目のトンネルは「ゴールの駅」へつながる。

### 2.4 グランドフィナーレ(駅)
- 駅のホームに汽車が到着し、貨車がすべて見える。汽車はホーム前の短いループを走り続け、全層が鳴る。
- 周りの木や家の窓がリズムに合わせて光り、紙吹雪が舞う。
- **貨車をタップするとその層の楽器が「ふた」で隠れて音が止まる**(ミュート)。もう一度タップで戻る。これがアレンジ操作。
- 駅の左に**新しい空の汽車**が待っている。それをタップすると、今の汽車は汽笛を鳴らして画面右へ去り、新しい汽車で 1 レベル目から始まる(=新しい曲)。

### 2.5 中断と再開
- 楽器の配置・レベル・貨車の内容・テンポは変更のたびに localStorage へ保存。
- 再起動時は「起動直後」の停車状態から始まり、最初のタップで保存された状態の続きを走り出す。

## 3. レベルと楽器

### 3.1 楽器(全 8 種、すべて合成音)

| 名前(内部 ID) | 見た目 | 種類 | 合成方法 |
|---|---|---|---|
| たいこ `drum` | 赤い丸太いこ | 打楽器 | サイン波ピッチスイープ + 短い減衰(キック) |
| かすたねっと `clap` | 木のカスタネット | 打楽器 | バンドパスしたノイズの短いバースト(スネア/クラップ) |
| しゃかしゃか `shaker` | 卵型マラカス | 打楽器 | ハイパスしたノイズ(ハイハット/シェイカー) |
| かね `bell` | 金色のベル | メロディ | FM 合成(倍音比 3.5)+ 長め減衰 |
| とり `bird` | 青い小鳥 | メロディ | サイン波 + ビブラート + 短い上向きグリッサンド |
| もっきん `marimba` | 木琴の板 1 枚 | メロディ | サイン波 + 4 倍音、短い減衰 |
| ふえ `flute` | 木の笛 | メロディ | 三角波 + ローパス + 緩いアタック(1 拍分伸びる) |
| かえる `frog` | 緑のかえる | ベース | 矩形波 + ローパス、低いオクターブ固定 |

- 音階: **C メジャーペンタトニック**(C D E G A)。ポール 5 段階にそのまま対応。レベルごとにオクターブが異なる(レベル 1: 低め、レベル 2: 中、レベル 3: 高め、レベル 4: ベース+装飾)。
- マスター: 全楽器 → コンプレッサ → 軽いリバーブ(ノイズから生成したインパルス) → 出力。音量は子ども向けに控えめ・急峻なアタックを避ける。

### 3.2 レベルの生成
- 4 レベル固定だが、**各レベルの色テーマと楽器 3〜4 種はシード付き乱数で選ぶ**(毎回少し違う)。
- 構成ルール: レベル 1 は必ず打楽器 2 種以上、レベル 2〜3 はメロディ中心、レベル 4 は `frog`(ベース)を必ず含む。
- 色テーマ(紙の色): 草原(緑/黄)、海辺(水色/砂)、雪(白/薄青)、夕焼け(橙/紫)などから抽選。

### 3.3 線路とタイミング
- 1 周 = 8 ステップ(8 分音符 × 8 = 2 拍子 2 小節相当)。テンポ 3 段階: 80 / 100 / 125 BPM。
- 汽車の位置は **AudioContext.currentTime から算出**し、描画とサウンドが必ず一致するようにする(描画側の時計に音を合わせない)。
- サウンドは lookahead スケジューラ(25ms 間隔、100ms 先読み)で予約。楽器を置いた直後に汽車がそこを通っても取りこぼさない。
- 各層(貨車)は同じ 8 ステップのグリッドを持ち、全層同時に走らせる。

## 4. 画面レイアウトと入力

- Canvas 1 枚を画面全体に敷く(`100dvh`、safe-area を考慮)。DPR 対応(上限 2 でパフォーマンス確保)。
- **縦画面**: 上 65% がジオラマ(楕円線路は縦長)、下 35% がおもちゃ箱。トンネルは上端。
- **横画面**: 左 75% がジオラマ、右 25% がおもちゃ箱。トンネルは右端。
- 回転時はレイアウトを再計算するだけで状態は保持。
- 入力は Pointer Events のみ。マルチタッチは「最初の指」だけ有効(2 本目は無視。ピンチ誤動作防止)。
- `touch-action: none`、`user-select: none`、`-webkit-touch-callout: none`、ダブルタップズーム防止、`apple-mobile-web-app-capable` 等のメタ設定。
- 楽器のドラッグ中は指の少し上に表示する(指で隠れないように)。

## 5. アーキテクチャ

```
src/
  main.ts              起動、Canvas/AudioContext 準備、ループ開始
  app/
    game.ts            状態機械(Waiting → Level → Transition → Finale)
    state.ts           曲の状態モデル(layers, placements, tempo, level)+ 型
    storage.ts         localStorage 保存/復元(バージョン付き JSON)
    levels.ts          レベル生成(シード乱数、色テーマ、楽器抽選)
  audio/
    context.ts         AudioContext のアンロックとマスターチェーン
    scheduler.ts       lookahead スケジューラ、汽車位置の計算
    instruments/*.ts   楽器ごとの合成(1 ファイル 1 楽器、共通 interface)
  render/
    canvas.ts          DPR 対応、リサイズ、レイアウト計算(縦/横)
    paper.ts           クラフト風描画ユーティリティ(紙の影、フェルトの縁、揺れ)
    scene.ts           ジオラマ・線路・穴・トンネル・箱の描画
    train.ts           汽車と貨車の描画・アニメーション
    effects.ts         紙吹雪、揺れ、脈打ち
  input/
    pointer.ts         Pointer Events 集約、ヒットテスト、ドラッグ状態
docs/                  プラン・記録
index.html
vite.config.ts         base: './'(どこに置いても動く相対パス)
```

- 状態は 1 つの plain object に集約し、描画は毎フレーム状態から描く(即時性を優先、仮想 DOM 不要)。
- 音と描画の唯一の時刻源は `AudioContext.currentTime`。

## 6. 実装ステップ(承認後)

1. **足場**: Vite + TS 初期化、`index.html`(メタ設定)、Canvas 全画面、DPR/リサイズ、縦横レイアウト。
2. **音**: AudioContext のアンロック、マスターチェーン、8 楽器の合成、スケジューラと汽車位置の同期。
3. **世界**: クラフト風描画、楕円線路と 8 穴、おもちゃ箱、汽車のアニメーション(蒸気・揺れ)。
4. **触る**: ドラッグ&ドロップ、穴の脈打ち、持ち上げ時の試し鳴らし、着地の弾み、通過時の揺れと紙吹雪、ポールでの音程変更、スコップでテンポ。
5. **重ねる**: トンネル扉、楽器が貨車に乗る演出、スクロール遷移、貨車の再生、レベル生成。
6. **フィナーレ**: 駅、貨車タップでミュート、新しい汽車で新規曲。
7. **保存**: localStorage 自動保存と復元。
8. **仕上げ**: 実機想定の性能確認(iPad 60fps 目標)、当たり判定の大きさ、音量バランス。
9. **記録**: `docs/02.md` に実装結果・確認方法・既知の問題を残す。

各ステップ完了ごとにコミットし、ブランチへプッシュする。

## 7. 検証方法

- **自動**: Vitest で状態モデル・スケジューラ(ステップ計算、テンポ変更時の連続性)・保存/復元をテスト。Playwright(同梱 Chromium、iPhone/iPad のビューポート+タッチ)でスモークテスト: 起動 → タップ → 楽器を穴へドラッグ → コンソールエラーなし、スクリーンショット取得。
- **手動(利用者)**: `npm run build` の `dist/` を任意の静的サーバに置き、iPhone/iPad Safari で確認。確認観点を `docs/02.md` にチェックリストとして記載する。

## 8. リスクと対策

| リスク | 対策 |
|---|---|
| iOS Safari で音が出ない(サイレントスイッチ・自動再生制限) | 最初のタッチでアンロック。サイレントスイッチはアプリ側で回避不可のため、確認手順に明記 |
| 描画と音のズレ | 時刻源を AudioContext に統一。描画は補間のみ |
| 4 層同時再生で音が濁る | 層ごとにオクターブ帯を分け、コンプレッサで抑える。同時発音数に上限 |
| 子どもがドラッグ中に画面外へ指を出す | `pointercancel`/`pointerleave` で必ず箱へ戻す |
| 縦画面で楽器箱が小さく掴みにくい | 楽器の最小サイズ 64px、箱は横スクロールせず 4 種以内に制限 |
