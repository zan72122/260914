## 1. 本家『Gorogoa』プレイ画像の詳細分析

添付5枚を、構造・操作・視覚言語の観点で分解した。ここで抽出した要素が、本作の「模倣すべき文法」になる。

### 1.1 画像1（カラス／リンゴの枝／屋根の鉢／空枠）
- **盤面**: 2×2の正方形グリッド。各セルは細い灰色枠。セル間は細い隙間。右下セルは**空**。
- **背景**: 羊皮紙のような生成り色。うっすらと鉛筆スケッチ（鳥、蔓、文字らしき走り書き）と、左右に赤い**スパイラル（渦巻き）模様**。スケッチは判読不能で「文字を読む」必要が生じない。
- **上段2枚は1枚の絵として連続**: 左上（枯れ枝にカラス、灰色の街）と右上（葉の茂る枝と赤いリンゴ、赤屋根の塔）は、枝が境界をまたいで**継ぎ目なく**つながる。左は無彩色寄り、右は彩度が高い＝「右側が生きている／注目すべき」という**彩度による誘導**。
- **左下**: 屋根と煙突の上に**青い鉢**が乗る。カーソルが鉢の近くにあり、これが次の操作対象であることを示す（鉢＝「何かを受ける器」という**知覚されたアフォーダンス**）。
- **右下の空セル**: 「ここに何かを置ける」という**知覚的不完全性**による誘い。

### 1.2 画像2（タイルをドラッグ中）
- 赤地に金の唐草＋青緑の花模様のタイルが、他タイルの**上に浮いて**ドラッグされている。影が落ち、盤面より一段手前にある。
- 下に見えるタイル群（螺旋飾りの塔／額縁のある部屋／青い鉢のズーム）は、ドラッグ中も**動かない**。ドラッグは「持ち上げて運ぶ」という物理的因果のメタファー。
- 左下は鉢の**ズームイン後**の状態（鉢が画面いっぱい、背景は灰色に脱色、緑の葉だけ色が残る）。＝「ズームで対象が主役になる」「色の残る部分が次の手掛かり」。
- 塔の頂上の螺旋飾りと背景の赤いスパイラルが**同じ形**。世界とUIを同じ図像言語で統一している。

### 1.3 画像3（鉢のズームイン）
- 左下セルが**台座の上の青い鉢**にズーム。鉢の口が広く、空。上段には枝のリンゴ。
- 構図: リンゴ（右上）と鉢（左下）が**同じ盤面にある**が、まだ縦に並んでいない。「リンゴを鉢の上に持ってくれば落ちる」と**重力という身近な物理因果**で予測できる。
- 操作結果の予告を**絵の配置だけ**で行っている点が本作で最も学ぶべき箇所。

### 1.4 画像4（青の曼荼羅／金の海馬と像／階段の少年／金の瓶）
- 中央のタイル（金の海馬、像、旗、ベル、ランプ、ガラス鐘）は**縦2セル分**の高さ。＝ズームアウトすると絵が複数セルにまたがることがある。
- 左上の青い曼荼羅は円形の装飾タイルで、内部に**小さな場面**（人物、鍵、部屋）が埋め込まれている。＝装飾の中に入口がある「入れ子」。
- 右の金の瓶は炎の上にあり、瓶の上部に丸い窓（穴）。＝**穴・窓は下のタイルを透かす**重ね合わせの入口。
- 左下の階段を降りる少年は、階段が**画面外**へ続く。＝隣接セルへの継ぎ目合わせを誘う。

### 1.5 画像5（カラス／開いた扉と額縁／街角の少年と柱）
- 右上: 開いた扉の奥に椅子。壁の**額縁の中にリンゴの枝**の絵。＝額縁は別シーンへの入口（額縁をタップ→ズームイン→そのシーンがタイルになる）。
- 右下: 少年が手押し車の前で、青い鉢が積み荷の上。隣の円柱に**真っ白な空のポスター枠**。＝「ここに絵を入れる」という不完全性。タイルを重ねて枠を埋める操作の誘い。
- 左下セルは空。カラスのタイルは彩度が落ちている（役目を終えた／今は関係ない）。

### 1.6 抽出した「Gorogoa文法」
| # | 文法 | 見せ方（文字なし） |
|---|---|---|
| G1 | タイル移動 | 持ち上がる・影・置ける枠が明るくなる |
| G2 | ズームイン | 絵の中の小さな「入口」（額縁・窓・器）をタップすると拡大 |
| G3 | ズームアウト | タイルを枠の外へ引くと一段引く |
| G4 | 境界合わせ | 枝・道・階段が隣セルへはみ出して途切れている |
| G5 | 重ね合わせ | 穴・窓・空枠の下に別タイルを置くと透ける |
| G6 | 受け渡し | 上のタイルの物が下のタイルへ落ちる（重力） |
| G7 | 彩度で誘導 | 関係ない場面は灰色、次の手掛かりだけ色が残る |
| G8 | 世界＝UI | メニュー・ボタン・文字なし。背景の飾りも世界の図像 |

## 2. Wordless interaction の設計ルール（本作の憲法）

1. **文字ゼロ**: タイトル、ボタン、ヒント、設定、エンディングを含め、画面に文字を出さない。HTMLの`<title>`とmanifestの名称だけは例外（画面には出ない）。
2. **説明の代わりに世界が誘う**: 次に触るべき物は「途切れている」「空いている」「色が残っている」「わずかに動いている」のいずれかで示す。
3. **身近な物理因果だけを使う**: 雨は下に落ちる、光は当たると明るい、道はつながると通れる。抽象ルールを作らない。
4. **即時の視覚フィードバック**: 触れた瞬間に持ち上がる、置けば揺れて収まる、正解なら世界が変わる。0.1秒以内に反応を出す。
5. **失敗状態を作らない**: どこへ置いても壊れない。間違った場所ではタイルが元の枠へ「ふわっと戻る」だけ。
6. **手が止まったら世界が動く**: 約15秒無操作で、次に触るべき対象が自然な動き（葉が揺れる、雲が流れる、タイルが少し浮く）で自己主張する。矢印・指・点滅枠は使わない。
7. **大きな当たり判定**: 4歳の指に合わせ、タップ対象は最小 64px（CSS px）、ドラッグ開始閾値は 8px。長押しは不要。
8. **一操作＝一結果**: ダブルタップ、二本指ジェスチャ、スワイプ方向判定を要求しない。ピンチ縮小は「あれば動く」補助扱い。

## 3. ゲーム仕様（試作：3パズル）

### 3.1 世界と物語
窓辺に置かれた小さな鉢の**種**が、**雨**を受けて芽吹き、**日の光**で蕾になり、**蝶**が来て花が開く。台詞・ナレーションなし。すべて絵の変化だけで語る。

### 3.2 タイル（初期4枚）
| ID | 場面 | 役割 |
|---|---|---|
| T1 部屋 | 窓辺のテーブルに鉢（土に種）。窓は**枠だけで中が空**（透ける穴） | 主役。ズームインで鉢が大写しになる |
| T2 雨雲 | 灰色の雲、下端から雨粒が**タイルの外へ**落ちかけて途切れている | 受け渡しの供給側 |
| T3 太陽 | 黄色い光が斜めに差す空 | 重ね合わせの供給側 |
| T4 庭 | 花壇と蝶。蝶の飛跡（点線の軌跡）が**右端で途切れる** | 境界合わせの供給側 |

### 3.3 パズル設計
**P1「あめ」（G1移動＋G6受け渡し）**
- 初期配置: T1=左下、T2=右上、T3=左上（灰色・無効）、T4=右下（灰色・無効）。
- 誘い: T2の雨粒がタイル下端で途切れ、下に何もない。T1の鉢の土は乾いて明るい茶色。T2だけ彩度が高い。
- 解: T2を左上（T1の真上）へドラッグ。雨がセル境界を越えて落ち、土が濃くなり**芽が出る**。
- フィードバック: 雨音→土色変化→芽の伸びるアニメ（1.5秒）。T2は役目を終え彩度が下がる。T3に色が戻る。

**P2「ひかり」（G2ズームイン＋G5重ね合わせ）**
- 誘い: T1の窓枠の中が空（白抜き）。T3の光線が窓の形と同じ向き。
- 解: T3を**T1の上に重ねる**（ドロップ先が空セルではなく既存タイルの場合、下に潜り込む）。窓枠の穴から太陽が見え、光が鉢に届き、芽が**蕾**になる。
- 補助操作: 鉢をタップするとT1がズームインし鉢が大写し（G2の練習）。ズーム中はタイル外側にドラッグで戻る（G3）。ズーム状態でもP2は成立する。
- フィードバック: 光の帯が窓→鉢へ伸びる、蕾の膨らみ、鳥の環境音が少し明るくなる。

**P3「ちょう」（G4境界合わせ＋G3ズームアウト）**
- 誘い: T4の蝶の飛跡が右端で途切れる。T1（蕾）のズームアウト状態では、窓の左に**外壁と飛跡の続き**が見える。
- 解: T4をT1の**左隣**に置く（T1が右列にある必要があるため、T1を右へ動かす／またはT4を左へ置く）。飛跡がつながると蝶が飛び移り、蕾にとまり、**花が開く**。
- エンディング: 4セル全体がゆっくり1枚の絵（花の咲いた窓辺と庭）に溶け合い、背景のスパイラルが花びらに変わる。文字なし。数秒後に静かにタイトル状態（＝最初の絵）へ戻り、再プレイ可能。

### 3.4 タイトル／セーブ
- タイトル画面は作らない。起動＝盤面。**初回は種のタイルだけが小さく揺れる**。
- 進行は`localStorage`に自動保存（パズル番号のみ）。リセットは花の絵を長押し3秒（唯一の隠し操作、子どもには不要）。

## 4. 技術設計

### 4.1 ファイル構成（予定）
```
index.html            盤面・SVG defs のホスト（文字なし）
manifest.webmanifest  PWA（standalone, 任意向き, アイコンはSVG）
css/app.css           レイアウト（2×2、縦横、セーフエリア）
js/main.js            起動、リサイズ、セーブ
js/board.js           グリッド状態、配置、重ね、スナップ
js/input.js           Pointer Events：タップ／ドラッグ／ズーム判定
js/tile.js            タイル（レイヤー付きSVG、ズーム段階）
js/puzzles.js         P1〜P3 の条件判定と演出トリガ
js/fx.js              アニメ（Web Animations API）
js/audio.js           Web Audio：効果音・環境音（風・鳥）
art/*.svg             各場面のSVG（<symbol>群、レイヤー分け）
docs/01.md            本プラン
```
ビルドツールなし。`file://`でも動くが、iOSでの音は初回タッチ後に`AudioContext.resume()`が必要。

### 4.2 データモデル
```js
// タイル
{ id:'T1', zoom:0,            // 0=全景, 1=鉢アップ
  layers:['bg','window-hole','pot','sprout'],   // SVG <g> 名
  edges:{ left:'butterfly-path', bottom:null }, // 境界合わせ用ソケット
  hole:{ shape:'window', accepts:['sun'] },     // 重ね合わせ用
  emits:{ side:'bottom', item:'rain' },         // 受け渡し用
  saturated:true }
// 盤面
{ cells:[[T3,T2],[T1,T4]], stacks:{ '0,1':[T1,T3] } }
```
パズル条件は「隣接関係」「重ね関係」「ズーム状態」の3述語の組合せで表現し、`puzzles.js`が毎フレームではなく**配置変更イベント時**に判定する。

### 4.3 入力（Pointer Events）
- `pointerdown`→8px移動で**ドラッグ**開始、移動なしで`pointerup`→**タップ**。
- ドラッグ中: タイルを`transform`で追従、`scale(1.04)`＋影。ドロップ候補セルの枠を明るくする。
- ドロップ: 空セル→移動、他タイル上→重ね（穴があれば下へ潜る／なければ元へ戻す）、盤外→元へ戻す。
- タップ: タイル内の`data-portal`要素なら**ズームイン**（SVG `viewBox`をアニメで変更）。
- ズームアウト: ズーム中のタイルを枠の外へ引く（G3）。ピンチ縮小も同じ結果に接続。
- `touch-action:none`、ダブルタップ拡大抑止、`user-select:none`、長押しコンテキストメニュー抑止。

### 4.4 レイアウト（縦横対応）
- 盤面は正方形。`size = min(vw, vh) - safe-area - 余白`。縦画面では上下、横画面では左右に羊皮紙背景（スケッチとスパイラル）が広がる。
- `env(safe-area-inset-*)` を考慮。`orientationchange`/`resize`で再計算。
- iPad横では最大 900px 程度に上限を設ける。

### 4.5 アート方針（SVG）
- 線画（濃灰の細線）＋淡い水彩風の塗り（半透明の多角形＋`feTurbulence`で紙目）。
- 各場面は`<symbol>`として`art/`に置き、`<use>`で組み立て。**画像差し替え時は`<symbol>`の中身を`<image>`に置換するだけ**で済む構造。
- 彩度制御は`filter: saturate()`で一括。

### 4.6 音（Web Audio）
- 効果音: 持ち上げ（短い木の音）、置く（コトン）、はまる（上向きの2音）、雨（ノイズ＋ローパス）、光（高音のパッド）、開花（アルペジオ）。
- 環境音: 風（フィルタ付きノイズをLFOで揺らす）、鳥（正弦波のグリッサンドをランダム間隔で）。
- iOSのミュートスイッチとバックグラウンドに従う（`visibilitychange`で停止）。

### 4.7 ヒント（世界が動く）
- 15秒無操作で、現在パズルの「供給側タイル」が 2px 浮き沈みし、「受け側」の対象（土・窓枠・飛跡の切れ目）がわずかに明るくなる。
- 45秒でさらに、供給側タイルが受け側の方向へ 6px だけ「傾く」。以降繰り返し。矢印・指・文字は出さない。
