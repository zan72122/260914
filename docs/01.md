# 01. プラン: おもちゃの電車セット（仮称 *Toy Train Set*）

Tracks – The Train Set Game 風の「木製電車セット」ゲームを、iPhone / iPad の Safari（縦・横どちらでも）で遊べる静的 Web アプリとして作る。
対象は 4 歳女児。**文字を一切使わない（Wordless interaction）** ことを最上位の制約とする。

> 状態: **承認待ち**。承認されるまで実装には着手しない。

---

## 0. 決定事項（ヒアリング結果）

| 項目 | 決定 |
| --- | --- |
| 描画 | 3D（Three.js）。上から見下ろす「おもちゃ箱ビュー」＋ 電車に乗り込む「運転席ビュー」 |
| 線路敷設 | 指で地面をなぞると、その軌跡に沿って木製レールが生える |
| 初回スコープ | 線路敷設 / 電車走行 / 運転席視点 / 飾り（木・家・動物・駅）/ 駅で乗客を運ぶ / 橋（立体交差） |
| 後回し | 分岐ポイント、複数電車、電車の塗り替え |
| 電車の操作 | 俯瞰ビュー: 電車をタップで発車、もう一度で停車。運転席ビュー: 画面内の大きなレバーで速度 |
| 線路の削除 | 線路を長押し → 揺れて浮き上がる → おもちゃ箱へ戻す（ドラッグ or 離すと戻る） |
| 音 | あり。Web Audio API で合成（音声ファイル不要） |
| カメラ | 固定（自動で線路全体が収まるように引く/寄る）。手動のカメラ操作なし |
| 配布 | 静的 Web（Vite ビルド → GitHub Pages）。PWA としてホーム画面に追加可 |
| 保存 | localStorage に常時自動保存。起動すると前回のおもちゃ箱がそのまま出る |
| ブランチ | `claude/toy-train-set` |

## 1. 設計原則: 世界そのものを UI にする

Wordless interaction のために、以下を**全画面・全操作に適用**する。

| 原則 | この作品での具体化 |
| --- | --- |
| **知覚されたアフォーダンス** | 触れるものは「触れそう」な形にする。電車は丸みのある木製玩具、レールの端は差し込み口（凸/凹）が見える |
| **サリエントなシグニファイア** | 触ってほしい物は**呼吸するように小さく上下**（idle bob）する。何も置かれていない起動直後は電車だけが動き、指を誘う |
| **物理的因果** | 指を動かす→その真下にレールが生える。電車を触る→動く。物を掴む→持ち上がって影が伸びる。離す→落ちて着地バウンド |
| **自然な写像** | 運転席レバーは前に倒す＝進む、手前に戻す＝止まる。レールは指の進行方向に伸びる |
| **知覚的不完全さ** | レールの端点は「まだ繋がっていない」ことが見えるよう、切れ端の枕木と開いた差し込み口を強調して脈動させる。閉じた環になると脈動が止まり「カチッ」と鳴る。駅に乗客が立って手を振る＝「迎えに来て」 |
| **即時の視覚フィードバック** | すべての入力に 100ms 以内で反応（ハイライト、パーティクル、音、スケール変化）。無反応を作らない |
| **文字・数字ゼロ** | HUD なし、メニューなし、設定画面なし、ダイアログなし。タイトル画面もなし（起動＝おもちゃ箱） |
| **取り返しがつく** | 削除は必ず「浮かせて戻す」段階を経る。誤操作で一気に消えない。全消しは提供しない（保存も自動） |
| **失敗がない** | 脱線・衝突・ゲームオーバーは存在しない。行き止まりに着いた電車は自動で向きを変えて戻る |

## 2. 画面と操作（Wordless 仕様）

### 2.1 おもちゃ箱ビュー（デフォルト）

- **世界**: 木のテーブルの上に、緑のフェルトのような柔らかい地面。周囲に少し暗い床。
- **画面下端（縦画面）/ 右端（横画面）**: 木の「おもちゃ箱」が少し開いた状態で見える。中身が少しはみ出しており、電車・木・家・動物・駅がのぞいている。
- **起動時**: 地面の中央に短いレール（1 本）と電車が 1 両だけ置いてある。レール端点の差し込み口が脈動する。

| 操作 | 結果 |
| --- | --- |
| 何もない地面を指でなぞる | 指の軌跡に沿って木製レールが生える（描画中は半透明のプレビュー、離すと着地音とともに実体化）。既存レール端点の近くから始めると自動で接続 |
| レール端点の近くで離す | 端点同士が磁石のように吸着して繋がる（「カチッ」＋小さな光） |
| 電車をタップ | 発車（汽笛 + 煙）。走行中にタップで停車（ブレーキ音） |
| 電車を長押し | 運転席ビューへズームイン（カメラが電車の中へ吸い込まれる） |
| おもちゃ箱の中の物を触って地面へドラッグ | 持ち上がる（影が伸び、少し傾く）→ 地面に落とすと着地バウンド＋音。レールの上には置けない（置こうとするとレールが赤くならず、物が**横に滑ってよける**） |
| 地面の飾りをドラッグ | 移動。おもちゃ箱の上で離すと箱に吸い込まれて消える |
| レール・飾りを長押し | 揺れて浮き上がる（iOS 風）。そのまま離すと元に戻る、おもちゃ箱へドラッグすると片付く |
| レールをなぞって既存レールと交差させる | 交差点で自動的に**橋**（木製の坂＋橋桁）が生える。電車が登る |
| 駅をレール脇に置く | ホームがレールに吸着。数秒後、乗客（木の人形）が現れて手を振る |
| 電車が駅に停車 | 乗客が乗り込む（乗車音）。別の駅に停まると降りて手を振り、キラキラ |

### 2.2 運転席ビュー

- 電車の前方を見る一人称カメラ。窓枠と計器（文字なしのメーター針）が見える。
- **右手**（縦画面では右下、横画面では右端）に大きな木製レバー。上方向にドラッグで加速、下で減速・停止。指を離してもレバー位置は保持。
- 左下に**紐のついた汽笛**。引っ張ると鳴る（乗客・動物が反応）。
- **戻り方**: 画面の左上に「後ろへ引く」アフォーダンスとして小さくなった俯瞰の世界（ピクチャ・イン・ピクチャ）を表示。それをタップ、または 2 本指ピンチイン、または電車が止まっているときに画面を下へスワイプ、のいずれでもおもちゃ箱ビューへ戻る。

### 2.3 縦画面 / 横画面

- CSS `100dvh` と `visualViewport` でセーフエリア込みのフルスクリーン。ホームバー領域は避ける。
- 縦: おもちゃ箱は下端。横: 右端。回転時はカメラが自動で再フレーミング。
- `touch-action: none`、ダブルタップズーム・長押し選択・スクロールバウンスを無効化。

## 3. 技術構成

```
toy-train-set/
├── index.html            # 1 ページ。文字なし。<title> のみ
├── public/
│   ├── manifest.webmanifest  # PWA（アイコン、standalone、orientation: any）
│   ├── icons/            # 木製電車のアイコン（SVG から生成）
│   └── sw.js             # オフラインキャッシュ
├── src/
│   ├── main.ts           # 起動、ループ、リサイズ
│   ├── world/            # Three.js シーン: テーブル、地面、ライト、影
│   ├── track/            # 線路: 軌跡→スプライン→レール生成、接続、橋
│   ├── train/            # 電車モデル、走行（スプライン上の弧長追従）、音
│   ├── props/            # 木・家・動物・駅、おもちゃ箱、乗客
│   ├── input/            # Pointer Events → ジェスチャー（tap/long-press/drag/draw）
│   ├── camera/           # おもちゃ箱ビュー（自動フレーミング）と運転席ビュー、遷移
│   ├── audio/            # Web Audio 合成（汽笛・走行・カチッ・着地・動物）
│   ├── save/             # localStorage 自動保存（デバウンス）と復元
│   └── fx/               # パーティクル、idle bob、揺れ、ハイライト
├── docs/                 # 計画書（本ファイル等）
├── package.json
├── vite.config.ts        # base はリポジトリ名に合わせる
└── .github/workflows/pages.yml   # main へ push で GitHub Pages に配信
```

- **言語/ツール**: TypeScript, Vite, Three.js（依存はこの 1 つ）。テストは Vitest（線路の幾何・接続ロジック・保存形式のユニットテスト）。
- **アセット**: 外部モデル・画像・音声ファイルは使わない。全てプロシージャル（Three.js プリミティブ＋頂点色、Web Audio 合成）。ロード待ちを作らない。
- **性能目標**: iPhone SE 相当で 60fps。レールは `InstancedMesh`（枕木・レール断片）、影はメインライト 1 灯の shadow map、`devicePixelRatio` は最大 2 に制限。

### 3.1 線路の内部表現

- ユーザーの指の軌跡（ワールド座標の点列）→ 間引き（Ramer–Douglas–Peucker）→ Catmull-Rom スプライン → 一定の弧長間隔でサンプルし、枕木とレールを生成。
- 最小曲率半径を設けて、指が急に曲がっても電車が走れる滑らかな曲線に**自動整形**する（子どもの手ぶれ吸収）。
- グラフ構造: `Segment`（スプライン）と `Node`（端点）。端点同士は吸着半径内で `Joint` になる。初回は分岐なし（各 Node の次数 ≤ 2）。
- **橋**: 新しいセグメントが既存セグメントと交差する場合、交差点前後に高さプロファイルを付与し、坂＋橋桁のメッシュを生成。交差角が浅すぎる場合は交差を避けるように軌跡を少しずらす。
- 電車の走行: セグメントの弧長パラメータで位置を進め、Joint を越えて隣のセグメントへ連続的に移る。行き止まりでは減速→停止→反転。

### 3.2 保存形式（localStorage）

```json
{ "v": 1,
  "segments": [{ "id": "s1", "pts": [[x,z],...], "a": "n1", "b": "n2" }],
  "joints": [["n2","n3"]],
  "props": [{ "type": "tree", "x": 0, "z": 0, "rot": 0 }],
  "train": { "seg": "s1", "t": 0.3, "dir": 1 } }
```

入力の 1 秒後にデバウンス保存。壊れていたら初期状態にフォールバック。

## 4. 実装ステップ（承認後に着手）

各ステップは動く状態で区切り、コミットする。

1. **足場**: Vite + TS + Three.js、フルスクリーン Canvas、iOS のジェスチャー抑止、リサイズ・回転対応、GitHub Pages ワークフロー、PWA manifest。
2. **世界**: テーブル・地面・ライト・影。おもちゃ箱ビューの自動フレーミング（内容の AABB に合わせてカメラ距離を補間）。
3. **線路描画**: 指の軌跡→スプライン→レールメッシュ。プレビュー、着地演出、端点吸着、端点の脈動。
4. **電車**: プロシージャルな木製機関車＋客車 1 両。スプライン追従、タップで発車/停車、行き止まり反転、煙・音。
5. **運転席ビュー**: 長押しで遷移、レバー、汽笛紐、PiP からの復帰、俯瞰↔運転席のカメラ補間。
6. **おもちゃ箱と飾り**: 箱のモデル、中身のはみ出し、ドラッグで取り出し・置く・片付ける、長押しで浮かせる（レールも同様に片付け可）。動物の反応。
7. **駅と乗客**: 駅のレール吸着、乗客の出現・手振り、乗降、到着のキラキラ。
8. **橋**: 交差検出、高さプロファイル、坂と橋桁メッシュ、電車の上下追従。
9. **自動保存・復元**、サービスワーカー、アイコン。
10. **磨き**: idle bob、パーティクル、触感の調整、iPhone/iPad 実機相当（Playwright の iPhone/iPad エミュレーション）でのスクリーンショット確認、性能調整。

## 5. 検証方法

- **Wordless チェックリスト**: 全画面をスクリーンショットし、文字・数字・アイコン的な記号（矢印・×・歯車）がゼロであることを確認。
- **初見テスト想定**: 起動直後 10 秒以内に、説明なしで (a) レールを描ける (b) 電車が動く、の 2 つが起きる導線になっているかを、動く要素（脈動する端点・呼吸する電車）で保証する。
- **自動テスト**: 線路の幾何（間引き・最小半径・吸着・交差検出）、走行の弧長計算、保存/復元の往復をユニットテスト。
- **実機相当**: Playwright で iPhone 15 / iPad（縦・横）のビューポートを再現し、各ステップで描画を確認。
