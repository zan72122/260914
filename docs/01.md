# 01. 企画・実装プラン — 「くずしてあそぼう」（Art Of Gravity 風・4歳向け）

状態: **承認済み・実装完了**（実装時の判断と差分は `docs/02.md`）

## 0. 決定済み事項（ヒアリング結果）

| 項目 | 決定 |
|---|---|
| 表現方式 | 3Dボクセル（Three.js + 物理エンジン） |
| 配布 | ローカルファイル起動（`index.html` をそのまま Safari / Files アプリで開く） |
| 失敗の扱い | 失敗なし・やり直し自由 |
| 規模 | 小（レベル10前後、ボール3種、ブロック4種、効果音あり） |
| 対象端末 | iPhone / iPad、縦横どちらでも |
| 対象年齢 | 4歳（文字を読めない前提。Wordless interaction 厳守） |

## 1. コンセプト

空中に浮かぶボクセル（立方体）の塊に、下から指でボールを投げてぶつけ、**全部くずして落とす**。
くずれたブロックは重力で落ち、画面の底に溜まって消える。全部消えたら、次の塊がふわっと降りてくる。

原作 Art Of Gravity の骨格（限られたボール × 性質の違うブロック × 崩壊の美しさ）を借り、
「パズルとして解く」より「見て、触って、崩れるのを眺めて気持ちいい」を最優先にする。

## 2. Wordless interaction の適用方針（世界そのものを UI にする）

文字・数字・アイコンボタン・チュートリアル画面は**一切置かない**。以下で代替する。

| 伝えたいこと | 世界での表し方 |
|---|---|
| 「ここを触る」 | 画面下部に**ボールが実体として転がっている**。指を近づけると（タッチ開始で）ボールが指に吸い付き、ほのかに光る。触れるものは触れそうに見える（perceived affordance）。 |
| 「投げる」 | ボールを引くとパチンコの**ゴムが伸びて見え**、進行方向に点線の軌跡が伸びる。離せば飛ぶ（familiar physical causality）。 |
| 「残り個数」 | 数字ではなく、**足元に並ぶボールの実物の数**。投げれば1個減るのが見える。 |
| 「ボールの種類」 | 見た目で性質が分かる：重い＝**鉄色で大きい・着地音が低い**、爆発＝**赤くて脈打つ**、通常＝**白くてまるい**。 |
| 「どのボールがどのブロックに効くか」 | ブロック側も同じ言語：鉄色ブロックは**普通ボールが弾かれてコツンと鳴る**（即時フィードバック）。鉄ボールをぶつけると砕ける。試せば分かる。 |
| 「操作方法」 | 何もしないで3秒経つと、**ボールが自分で小さくぴょこんと跳ねる**（誘い）。さらに待つと半透明の指の影がボールを引いて放す様子を1回だけ演じる（demonstration）。 |
| 「クリア」 | 最後のブロックが落ちた瞬間、光の粒が舞い、カメラがゆっくり寄って、次の塊が上から降りてくる。ボタンなし。 |
| 「ボールが尽きた」 | 失敗表示は無し。残ったブロックが**ふわっと浮いて元の形に戻り**、足元にボールが**転がって戻ってくる**（巻き戻し）。数秒眺めるだけで再挑戦できる。 |
| 「やり直したい」 | 画面のどこでもいいので**2本指で画面をなでる**か、端末をシェイクするとブロックが元に戻る。ただしメイン導線ではない（尽きれば自動で戻るため）。 |
| 「前のレベルに戻る」 | 空中の塊の奥に、クリアした塊の**小さな残像**が並んで見え、タップすると呼び戻せる。（初期スコープでは任意・後回し） |
| 「音を出す/止める」 | 設定 UI は置かない。端末のマナーモード・音量ボタンに従う。 |

補足原則:
- **知覚的不完全さ**（perceptual incompleteness）: 塊は常に「あと少しで崩れそう」なバランスで組む。1つ抜けば連鎖して落ちる箇所を必ず用意し、どこを狙えばいいかを形が語る。
- **自然な対応**（natural mapping）: 指を左に引けば右に飛ぶ、ではなく**引いた逆方向へ**飛ぶパチンコ様式。下から上に投げるので、重力と向きの関係も見た通り。
- **即時フィードバック**: 命中・弾かれ・砕ける・落ちる・消えるの5イベントに、それぞれ音・光・粒子・軽い振動（Haptics API が使える場合のみ）を割り当てる。

## 3. ゲームルール

### 3.1 進行
1. 起動 → ロゴやタイトル画面は**無し**。即座にレベル1の塊が上から降りてきて、足元にボールが転がる。
2. ボールを引いて放つ。ブロックに当たると性質に応じて砕ける/押される。
3. 砕けた欠片・支えを失ったブロックは重力で落下。画面下端（見えない床）に触れたら短くきらめいて消える。
4. **全ブロックが消える** → クリア演出 → 次レベル。
5. ボールが尽きても残っていれば、巻き戻し（§2）。**失敗の概念は無い**。
6. 最終レベルクリア後はレベル1に戻る（ループ）。進行は `localStorage` に保存し、次回起動時は前回のレベルから。

### 3.2 ボール（3種）
| 種類 | 見た目 | 性質 |
|---|---|---|
| しろ（通常） | 白く光る球 | ふつうブロックを砕く。鉄ブロックには弾かれる。 |
| てつ（重い） | 濃い金属色・少し大きい | 何でも砕く。軌道が低く速く落ちる。当たった場所を強く押す。 |
| ばくはつ | 赤く脈打つ | 当たった瞬間に周囲一定半径のふつうブロックを一気に砕く。鉄は砕けないが**吹き飛ばす**。 |

各レベルで用意されるボールの内訳・個数はレベルデータで指定。足元に実体として並ぶ。

### 3.3 ブロック（4種）
| 種類 | 見た目 | 性質 |
|---|---|---|
| ふつう | 薄いパステル色（レベルごとに色相を変える） | 当たると砕けて欠片になり落ちる。 |
| てつ | 濃い金属色 | 通常ボールを弾く。てつボール・爆発の吹き飛ばしで動く/砕ける。 |
| ガラス | 半透明・キラキラ | 少しの衝撃で砕ける。連鎖の起点。 |
| くも（浮き） | 白くふわふわ・ゆっくり上下 | 重力の影響を受けず塊を支えている。壊すと支えを失った塊が全部落ちる（大崩落の演出担当）。 |

### 3.4 レベル（初期スコープ 10）
段階的に1つずつ概念を導入する（教えるのではなく、遭遇させる）。

| Lv | 導入する概念 | 内容案 |
|---|---|---|
| 1 | 投げる・崩れる | ふつうブロックだけの低い塔。ボール3個。どこに当てても崩れる。 |
| 2 | 狙う | 細い柱の上に塊。柱を抜けば全部落ちる。 |
| 3 | 連鎖 | ガラスの支柱。少し触るだけで崩れる。 |
| 4 | 弾かれる | 中央に鉄ブロック1個。しろボールは弾かれる。てつボールが1個混ざっている。 |
| 5 | てつボールを選ぶ | 鉄ブロックが多め。しろで壊せる部分とてつで壊す部分が視覚的に分かれる。 |
| 6 | 爆発 | ばくはつボール初登場。ぎゅっと密な塊。 |
| 7 | くも | くもブロックが塊を支えている。くもを撃つと全部落ちる。 |
| 8 | 組み合わせ | 鉄の殻の中にガラス。 |
| 9 | 大崩落 | 高い塔をくもが支える。てつ＋ばくはつ。 |
| 10 | ごちそう | すべて登場する大きな塊。ボール多め。眺めて気持ちいい締め。 |

レベルは JSON（ボクセル座標 + 種類、ボール構成）で記述し、後から追加しやすくする。

## 4. 画面・操作（縦横両対応）

- カメラは塊の正面やや下から見上げる固定視点。**視点操作は無し**（4歳には不要な自由度）。
- 縦画面: 塊が上、ボールの足場が下。横画面: 塊が中央上、足場が下端。画面比に応じて塊がフレーム内に収まるようカメラ距離を自動調整。
- 入力はシングルタッチのドラッグのみ（`pointer` イベント）。マルチタッチはリセット用途のみ。
- ピンチズーム・スクロール・長押し選択・ダブルタップ拡大を CSS / `touch-action: none` / `preventDefault` で全て封じる。
- `viewport-fit=cover`、セーフエリアを考慮し、ボール足場がホームバーと重ならない位置に置く。
- 全画面は Safari 上で「共有→ホーム画面に追加」すれば `apple-mobile-web-app-capable` でフルスクリーンになる（PWA 化はしないが meta タグだけ入れる。ローカルファイルでも無害）。

## 5. 技術構成

### 5.1 スタック
| 役割 | 採用 | 理由 |
|---|---|---|
| 描画 | Three.js（r16x） | iOS Safari の WebGL2 で安定。ボクセル＝`InstancedMesh` で軽量。 |
| 物理 | cannon-es | 純 JS・依存なし。`file://` でも WASM 読み込みの問題が無い。小規模なら十分。 |
| 音 | Web Audio API（合成音） | 音声ファイル不要、`file://` の fetch 制限を回避。命中音・砕け音・きらめき音を合成。 |
| ビルド | esbuild（開発時のみ） | `src/` を1ファイルにバンドル → `index.html` にインライン。 |
| 言語 | JavaScript（ES2020）+ JSDoc | ビルド最小化。 |

### 5.2 ローカル起動の制約への対処
iOS Safari の `file://` では ES modules・fetch・WASM の読み込みが不安定なため、
**成果物は単一 `index.html`（JS・レベルデータ・全てインライン）** とし、リポジトリに**ビルド済みでコミット**する。
これでビルド環境なしでも、ファイルを iPhone に転送して開けば動く。

### 5.3 ディレクトリ
```
index.html              # ビルド済み・単一ファイル（コミットする）
src/
  main.js               # 起動・ループ
  scene.js              # Three.js シーン・カメラ・レスポンシブ
  physics.js            # cannon-es ラッパ、ボクセル↔ボディ同期
  voxel.js              # ブロック種類・砕け処理・欠片生成
  ball.js               # ボール種類・パチンコ操作・軌跡表示
  levels.js             # レベルデータ（JSON 相当）
  fx.js                 # 粒子・光・クリア演出・巻き戻し演出
  audio.js              # 合成効果音
  invite.js             # 無操作時の誘い（ぴょこん・指の影）
  storage.js            # 進行保存
build/
  build.mjs             # esbuild → index.html 生成
docs/
  01.md                 # このプラン
package.json
```

### 5.4 パフォーマンス方針
- ブロックは最大 ~150 個/レベル、欠片は 1 ブロック → 4 個に分裂、床に着いたら即消去。
- 同時アクティブ物理ボディ上限 ~400。超えたら古い欠片から消す。
- `devicePixelRatio` は 2 で上限。影は無し、ライトは 2 灯。ブロックの見分けは色と質感で。
- 目標 60fps（iPhone 11 相当以降）。

## 7. 検証方法

- Playwright（Chromium）で iPhone 縦 / iPhone 横 / iPad 縦 の 3 ビューポートを起動し、以下を自動確認:
  - 起動直後にテキスト要素が DOM 上に存在しない（Wordless の機械的チェック）
  - ドラッグ→リリースでブロック数が減る
  - 全ブロック消去で次レベルに遷移する
  - ボール尽きで巻き戻しが起きブロック数が復元する
- 実機は利用者側で `index.html` を AirDrop / Files アプリから Safari で開いて確認。

## 8. 承認前に確認したい残論点（任意・未回答なら推奨案で進める）

1. **色調**: 推奨＝背景は深い藍〜夜空、ブロックは明るいパステル（レベルごとに色相を変える）。原作の白黒ミニマルより、崩れる欠片が背景に映える配色。
2. **端末シェイクでのリセット**: 推奨＝入れる（誤作動しにくい閾値で）。不要なら外す。
3. **前のレベルへ戻る導線**（§2 末尾）: 推奨＝初期スコープから外し、M6 以降で検討。
