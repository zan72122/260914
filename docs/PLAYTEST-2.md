# プレイテスト2（初見4歳児プロキシ / ブラインド）

テスター: 「文字が読めない・大人の説明ゼロ・音は聞こえない」4歳児の代理。
ソースコード・docs・testsは一切読まずに、画面のピクセルと指だけで実施。

## 環境

- サーバ: `python3 -m http.server 8171`（リポジトリ直下） → `http://127.0.0.1:8171/`
- ブラウザ: Playwright + Chromium（`/opt/pw-browsers/chromium`）
- セッションA: iPhone縦 390×844 / `hasTouch:true` `isMobile:true` / DPR 3
- セッションB: iPad横 1180×820 / `hasTouch:true` `isMobile:true` / DPR 2
- 入力: CDP `Input.dispatchTouchEvent`（touchStart→touchMove×20前後→touchEnd、0.6〜1.0秒、座標に数px のブレを混ぜた「雑な指」）
- 音声: 聞こえない前提（評価対象外）。ゲーム内に文字は無し。
- スクリーンショット: `docs/playtest2/`（横300px、18枚）

補足: プロセスを跨いでCDP再接続すると描画が真っ白になる現象があり（Playwright側の再エミュレーション起因と思われる）、各ステージは1プロセス内で通しで実行した。ゲーム自体の不具合かは未確認だが、**一度ページを表示したあとに外部から再アタッチすると画面が消える**のは記録しておく。

### 触る前の素朴な予想（BEFORE）

> 「ぬれてるお洋服を、下の おおきい かごに いれるんだと思う。
> いちばん きいろくて めだつ タオルを ゆびで つまんで、かごまで ひっぱる。」

つまり「対象＝洗濯物」「方向＝下（カゴ）」。これは画面から自然に出てきた。
一方で、**最後にサッシを閉めるという発想は12秒観察の時点ではゼロ**だった（窓が「開いている」ことに気づいていない）。

## 最後のサッシ（窓を閉める）

### 絵から「やりたい」と思ったこと（推測を書いてから試行）

ロープが空っぽになった瞬間の画面（`08_empty_line_glow.png`）を見て思ったこと:

> 「もう ふく が ないのに、まだ あめが ふってる。
> まんなかへんの まるいの（＝取っ手）が **ぼわっと ひかってる** から、そこを さわる。」

光っているハンドル（ふんわりした白い後光が付く）に目が行った。ただし、**「窓が開いている」とは分かっていない**。子どもの理解は「光ってるボタンを押す」レベル。

| 試行 | 内容 | 結果 | 判定 |
|---|---|---|---|
| 1 | 光っている取っ手を**タップ**（一番自然な「押す」） | **何も起きない**。光り続けるだけ。フィードバックゼロ | **×** |
| 2 | 取っ手を**つかんで左へドラッグ**（開口部がある側＝左に引く） | ガラス戸が指に追従してスーッと閉まる。閉め切ると全面がガラス越しの雨になり、**子どもが両手を挙げて万歳＋ほっぺが赤く**なる。明確なクリア感 | **○** |

サッシ = **2試行（うち1失敗）**。

## 最重要QA項目の総合判定

> **「初見の4歳児が、大人の説明なしで雨に気づき、最初の一枚を取り込めるか」**

### 判定: **○**

理由:

1. **雨への気づき（○）**: 6秒前後で空が暗転し、雨脚・水たまり・布の濃いシミ・キャラの「上を指す」ポーズが同時に出る。文字ゼロでも「なんか降ってきた、お洋服がぬれてる」は伝わる。
2. **最初の一枚（◎）**: 「目立つものをつまんで、下のカゴへ引っぱる」という4歳の最も素朴な仮説が**そのまま1回で通る**。当たり判定が広く、掴む位置も離す位置も雑でよい。空振り・ペナルティが無い。
3. **即時フィードバック（◎）**: 布が指に追従して伸びる、キャラが歩いて近寄る、カゴの中身が色の層として積み上がる、と3段階で「できた」が返る。
4. 減点要因: 3秒に出る**大きなツヤ玉が雨粒に見えない**（風船/シャボン玉に見える）、キャラの指差しが「どこへ運ぶか」を示さない、といった弱さはあるが、最初の一枚の成否そのものは阻害しない。

補足判定:
- 洗濯物を全部取り込む: **○**
- 最後にサッシを閉める: **△**（光るヒントは出るが、最初の「タップ」が完全に無反応。ドラッグに気づけるかは運。今回は2回目で成功したが、タップを繰り返して詰まる子は十分あり得る）

## 改善提案（優先順位付き・最大7件）

1. **【最優先】サッシのタップに反応を付ける**
   光る取っ手をタップしたとき、現状は完全な無反応。せめて取っ手が少し左へ動いて戻る（＝「引くんだよ」を示す）か、タップだけでも閉まるようにする。4歳が最初に選ぶ操作はドラッグではなくタップ。
2. **【高】サッシを閉める方向を絵で示す**
   ロープが空になったら、取っ手から左向きに動く矢印／残像／ゴースト手を1〜2回ループ表示する。「光る＝押す」ではなく「光る＝この向きに引く」に読み替えさせる。
3. **【高】最初の雨粒の見た目を変える**
   3秒時点の大きな灰色のツヤ玉は、4歳には風船・シャボン玉に見える。雫型にする／落下しながら床で弾けて小さな水紋を作る／数を増やして小さくする、のいずれかで「雨」だと即断できるようにする。
4. **【中】キャラの指差しに「行き先」を足す**
   現状は上を指すだけ。上を指す → カゴを指す → の2モーションにする、または洗濯物からカゴへ薄い軌跡（点線アーチ）を1回だけ流すと、方向の仮説がゼロ手で立つ。
5. **【中】ドラッグ中断・回転時の布の描画を安定させる**
   画面回転を挟むと掴んでいた布が画面を斜めに横切る細長い形になり、離しても歪んだ姿で残る。リサイズ検知時はドラッグを中断して元の形に即スナップさせる。逆方向ドラッグ後に捻れたまま残るのも同様。
6. **【中】iPad横のレイアウトで距離を縮める／雨を強く見せる**
   洗濯物とカゴが画面の両端で1ドラッグ約1000px。カゴをもう少し中央寄りに置く、または「離せばどこでもカゴへ飛ぶ」現在の寛容さを明示的に見せる（離した瞬間に軌跡を描く）。横向きでは雨脚が細く見えるので、画面幅に応じて雨の本数・太さをスケールさせる。
7. **【低】カゴ自身にも「ここへ入れる」誘いを持たせる**
   雨が降り始めたらカゴの縁がふわっと明滅する、カゴをタップしたら口がぱかっと開く等。今回は不要だったが、キャラをタップし続けて止まる子への保険になる。
