## 2. シーンの状態機械

### シーン1 「あつまれ」(`01_gather.ts`)

```
scatter ──(全員が waver から CLUSTER_RADIUS=330 以内)──> clapping
clapping ──(1.5秒)──> running
running  ──(全員が exitX を越える / 4秒)──> done ──> Director がパン
```

- **scatter**: 中央の一人だけが手を振り続ける。その他は視界いっぱいに散らばる(開始時、中央 396 単位は必ず空ける)。
  タップ = 指の位置へ近くの子が歩く。ドラッグ = 指に触れた子が指について歩く。
  waver の近く(半径の 95%)まで来た子は、waver のまわりの黄金角スロットに落ち着く(密集させない)。
- **clapping**: 全員 `clap` + パステルの紙吹雪 + `clap` 音。
- **running**: 全員 `run`。目標は画面外はるか右。
- 無操作ヒント(8〜12秒): 3人が自分から waver へ歩き出し、waver は 1.28 倍に大きく手を振る。
- 自動進行(30秒): 全員が自分のスロットへ歩き出す。

### シーン4 「ボールプール」(`04_ballpit.ts`)

```
rim ──(全員がプールの中)──> overflow
overflow ──(1.6秒)──> running
running  ──(全員が exitX を越える / 4秒)──> done ──> Director がパン
```

- **rim**: 26人が縁に立ち、60個のボールが跳ねている。
  子をタップ / 子の近くのプールをタップ = 最寄りの最大3人が飛び込む。
  ドラッグで子を縁の内側へ運んでも同じ(位置が円の中に入った瞬間に落ちる = 純粋な因果)。
  飛び込み: `jump` ポーズ → 0.55秒の放物線 → 着地でボールが弾け、`pochan` + `rattle`。
  中の子はボールの間で上下に揺れ、ときどき笑う。
- **overflow**: `BallPool.spill()`。ボールは右へ転がり出て、子も一緒に出てくる。紙吹雪と `rattle`。
- **running**: 全員 `run`。
- 無操作ヒント: 縁の一人が 2.4 秒つま先で跳ね、一番上のボールが縁を越えて跳ね、また戻る。
- 自動進行: 0.55 秒ごとに一人ずつ自分から飛び込む。

ボールは `layer`(kid と同じ sortable コンテナ)に `zIndex = y` で入れてあるので、
プールの中の子は**ボールに挟まれて**描画されます(前後関係が自然)。

## 3. デバッグフック(`window.__kids`)

画面には何も出しません。E2E とデバッグ専用です。

| フック | 返すもの |
|---|---|
| `ready` | 起動完了 |
| `textCount()` | ステージ上の Pixi テキスト数(常に 0) |
| `kidCount()` | 現在のシーンの子の数 |
| `sceneName()` | `'gather'` / `'ballpit'` |
| `sceneIndex()` | 進行順の番号 |
| `scenePhase()` | 上記の状態機械の状態名 |
| `sceneProgress()` | 0..1 |
| `panning()` | カメラがパン中か |
| `autoFired()` | 30秒の自動進行が発動済みか(E2E が「本当に指で進めた」ことを証明するのに使う) |
| `advanceScene()` | 次のシーンへ |
| `finishScene()` | 現在のシーンを終わりまで進める |
| `idleHint()` / `autoAdvance()` | 無操作ヒント / 自動進行を手動で発火 |
| `fps()` | 実測 FPS |

## 4. 端末サイズの方針(重要)

セーフゾーンは 1000 単位の正方形のまま、**縦横どちらでも必ず収まる**という 01.md の約束を維持しています。
そのため iPhone(390幅)では world→screen 倍率が 0.39 に固定されます。
文字が読めない4歳児に対して子どもが 43px では小さすぎたので、
**セーフゾーンを縮めるのではなく、子の世界サイズを 110 → 150 単位(セーフゾーンの 15%)に拡大**しました。

- iPhone 390 幅 → 150 × 0.39 = **58.5 CSS px**
- iPad → 約 154 CSS px
- 分離半径なども 150/110 倍にしたので、群衆の見た目の密度は Phase 0 と同じ

この判断は `src/art/kidSheet.ts` の `KID_WORLD_H` のコメントに、根拠つきで書いてあります。
`tests/viewport.test.ts` が「iPhone で 56px 以上 かつ セーフゾーンが収まる」を両方検査します。

## 5. 仕様との差分

1. **シーン1のドラッグ**: 01.md は「ドラッグで引き寄せ」。実装では、押している指に触れた子は
   指そのものを目標にして**ついて歩く**(指を動かすと列が follow する)。
   「引き寄せ」より強い挙動ですが、4歳児が画面を撫でるだけで遊べるようにするために必要でした。
2. **プールの大きさ**: 縦画面では可視世界の幅が常に 1000 単位しかないため、プールは固定で
   半径 310 単位。回転してもプール(とボールの物理)を作り直さなくて済みます。
3. **`00_playground.ts` の削除**(上記)。

01.md 本体は変更していません。

## 6. iPad で試す(同一 Wi-Fi)

```
npm install
npm run dev
```

ターミナルに出る `Network:` の URL(例 `http://192.168.x.x:5173/`)を iPad の Safari で開きます。
Mac / PC と iPad が同じ Wi-Fi にいる必要があります。

そのあと **共有 → ホーム画面に追加**。ホーム画面のアイコンから起動すると、
Safari の UI が消えて全画面になります(`manifest.json` + `apple-mobile-web-app-capable`)。

- 最初のタッチまで音は鳴りません(iOS の自動再生制限)。これは仕様どおりで、
  それまでの画面は視覚だけで成立します。
- 縦でも横でも、回転しても、シーンは途切れません。
- ビルド済みのものを配る場合は `npm run build && npm run preview`(こちらも `--host` 済み)。
